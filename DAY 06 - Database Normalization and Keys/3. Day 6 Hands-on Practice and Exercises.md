# Day 06: Chapter 3 — Hands-on Practice & Exercises

This guide contains practical exercises designed to test your knowledge of database keys, anomalies, and normalization techniques (1NF, 2NF, and 3NF).

---

## 📊 Practice Scenario: Course Registration System

Imagine a university registrar's office is keeping track of student course enrollments in a single wide spreadsheet table:

### `CourseRegistration` Table
| student_id | student_name | course_id | course_name | instructor_name | instructor_office | grade |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | Rahul | CS101 | Databases | Dr. Sharma | Room 302 | A |
| 1 | Rahul | CS102 | Algorithms | Dr. Verma | Room 305 | B |
| 2 | Priya | CS101 | Databases | Dr. Sharma | Room 302 | A+ |
| 3 | Amit | CS103 | Networks | Dr. Patel | Room 401 | B- |

---

### Q1. Identify the candidate key(s) and define the composite primary key.
*   **Analysis:**
    - A student can enroll in multiple courses, and a course can have multiple students.
    - Neither `student_id` nor `course_id` is unique alone.
    - To uniquely identify each grade enrollment record, we must combine them.
*   **Solution:** The composite primary key is **`{student_id, course_id}`**.

---

### Q2. Identify database anomalies (Insertion, Update, Deletion) in this table.
*   **Insertion Anomaly:**
    - We cannot add a new course or instructor to the system unless at least one student registers for it (because `student_id` is part of the composite primary key and cannot be `NULL`).
*   **Update Anomaly:**
    - If Dr. Sharma moves to a new office, we have to update the office room number in multiple records (every student enrolled in CS101). If we miss any row, the data becomes inconsistent.
*   **Deletion Anomaly:**
    - If Amit drops out and we delete his row (student 3), we also completely delete the information that course CS103 is "Networks", and that Dr. Patel teaches in Room 401.

---

### Q3. Identify partial dependencies and decompose the table into 2nd Normal Form (2NF).
*   **Analysis:**
    - The primary key is `{student_id, course_id}`.
    - `grade` depends on both `{student_id, course_id}` (Full dependency).
    - `student_name` depends **only** on `student_id` (Partial dependency).
    - `course_name`, `instructor_name`, and `instructor_office` depend **only** on `course_id` (Partial dependency).
*   **Decomposition (2NF Tables):**
    - We extract the partial dependencies into their own tables.

#### 1. `Students` Table (PK: `student_id`)
| student_id | student_name |
| :--- | :--- |
| 1 | Rahul |
| 2 | Priya |
| 3 | Amit |

#### 2. `Courses` Table (PK: `course_id`)
| course_id | course_name | instructor_name | instructor_office |
| :--- | :--- | :--- | :--- |
| CS101 | Databases | Dr. Sharma | Room 302 |
| CS102 | Algorithms | Dr. Verma | Room 305 |
| CS103 | Networks | Dr. Patel | Room 401 |

#### 3. `Enrollments` Table (Composite PK: `{student_id, course_id}`)
| student_id | course_id | grade |
| :--- | :--- | :--- |
| 1 | CS101 | A |
| 1 | CS102 | B |
| 2 | CS101 | A+ |
| 3 | CS103 | B- |

---

### Q4. Identify transitive dependencies in the 2NF tables and decompose into 3rd Normal Form (3NF).
*   **Analysis:**
    - Look at the `Courses` table (PK: `course_id`).
    - `instructor_name` depends on `course_id` ($course\_id \rightarrow instructor\_name$).
    - `instructor_office` depends on `instructor_name` ($instructor\_name \rightarrow instructor\_office$).
    - Therefore, `instructor_office` depends transitively on `course_id` ($course\_id \rightarrow instructor\_name \rightarrow instructor\_office$).
*   **Decomposition (3NF Tables):**
    - We extract the instructor details into a separate table to resolve the transitive dependency.

#### 1. `Students` Table (PK: `student_id`)
*(Unchanged from 2NF)*
| student_id | student_name |
| :--- | :--- |
| 1 | Rahul |
| 2 | Priya |
| 3 | Amit |

#### 2. `Instructors` Table (PK: `instructor_name`)
| instructor_name | instructor_office |
| :--- | :--- |
| Dr. Sharma | Room 302 |
| Dr. Verma | Room 305 |
| Dr. Patel | Room 401 |

#### 3. `Courses` Table (PK: `course_id`, FK: `instructor_name`)
| course_id | course_name | instructor_name |
| :--- | :--- | :--- |
| CS101 | Databases | Dr. Sharma |
| CS102 | Algorithms | Dr. Verma |
| CS103 | Networks | Dr. Patel |

#### 4. `Enrollments` Table (Composite PK: `{student_id, course_id}`)
*(Unchanged from 2NF)*
| student_id | course_id | grade |
| :--- | :--- | :--- |
| 1 | CS101 | A |
| 1 | CS102 | B |
| 2 | CS101 | A+ |
| 3 | CS103 | B- |
