### Task 1: Create a Secure Filtering View
Create a view named `v_delhi_customers` that displays only the `customer_id`, `name`, and `city` of customers located in 'Delhi' (hiding their sensitive email addresses). Enforce that no customer from other cities can be inserted or modified through this view.
*   **Query:**
    ```sql
    CREATE VIEW v_delhi_customers AS
    SELECT customer_id, name, city
    FROM Customers
    WHERE city = 'Delhi'
    WITH CHECK OPTION;
    ```

---

### Task 2: Create a Complex Join View
Create a view named `v_customer_sales` that combines customer details with their orders, showing `name` (as customer_name), `product`, and `amount`.
*   **Query:**
    ```sql
    CREATE VIEW v_customer_sales AS
    SELECT c.name AS customer_name, o.product, o.amount
    FROM Customers c
    INNER JOIN Orders o ON c.customer_id = o.customer_id;
    ```
*   **Verify view output (`SELECT * FROM v_customer_sales`):**
    | customer_name | product | amount |
    | :--- | :--- | :--- |
    | Rahul | Laptop | 55000.00 |
    | Priya | Mobile | 15000.00 |
    | Rahul | Earbuds | 3000.00 |

### Task 3: Test Updatable View Operations
Write statements to test updates and inserts through our views.

*   **Task 3a: Update a customer's name through `v_delhi_customers`:**
    ```sql
    UPDATE v_delhi_customers
    SET name = 'Rahul Sharma'
    WHERE customer_id = 1;
    ```
    *   *Result:* This should succeed, updating the name in the underlying `Customers` table.

*   **Task 3b: Insert a new Delhi customer through `v_delhi_customers`:**
    ```sql
    INSERT INTO v_delhi_customers (customer_id, name, city)
    VALUES (4, 'Sanjay', 'Delhi');
    ```
    *   *Result:* This should succeed, inserting Sanjay into the base table.

*   **Task 3c: Attempt to insert a Mumbai customer through `v_delhi_customers`:**
    ```sql
    INSERT INTO v_delhi_customers (customer_id, name, city)
    VALUES (5, 'Karan', 'Mumbai');
    ```
    *   *Result:* This **fails** because Karan's city is 'Mumbai', which violates the view's condition (`city = 'Delhi'`).
    *   *Error Output:* `ERROR 1369 (HY000): CHECK OPTION failed 'day9_practice.v_delhi_customers'`

## 📝 Section 2: Student Database Practice & Exercises


### 🔹 Basic Level Exercises

#### Q1. Create a view that shows only student ID and name.
*   **Solution Query:**
    ```sql
    CREATE VIEW student_id_name AS
    SELECT sid, sname
    FROM student8;
    ```

#### Q2. Create a view that displays student names and marks only for the 'Maths' course.
*   **Solution Query:**
    ```sql
    CREATE VIEW maths_students AS
    SELECT sname, marks
    FROM student8
    WHERE course = 'Maths';
    ```

#### Q3. Create a view that hides phone numbers (shows all columns except `phone`).
*   **Solution Query:**
    ```sql
    CREATE VIEW student_no_phone AS
    SELECT sid, sname, course, marks
    FROM student8;
    ```

#### Q4. Select data from the view created in Q1.
*   **Solution Query:**
    ```sql
    SELECT * FROM student_id_name;
    ```

#### Q5. Drop the view created in Q2.
*   **Solution Query:**
    ```sql
    DROP VIEW maths_students;
    ```

### 🔹 Intermediate Level Exercises

#### Q6. Create a view that shows students who scored more than 80 marks.
*   **Solution Query:**
    ```sql
    CREATE VIEW high_scorers AS
    SELECT *
    FROM student8
    WHERE marks > 80;
    ```

#### Q7. Create a view that shows course-wise average marks using `AVG(marks)`.
*   **Solution Query:**
    ```sql
    CREATE VIEW course_avg_marks AS
    SELECT course, AVG(marks) AS avg_marks
    FROM student8
    GROUP BY course;
    ```

#### Q8. Alter a view to include `phone` column in the result. (Alter the view from Q1).
*   **Solution Query:**
    ```sql
    ALTER VIEW student_id_name AS
    SELECT sid, sname, phone
    FROM student8;
    ```

#### Q9. Create a view that displays only Science students’ names and marks.
*   **Solution Query:**
    ```sql
    CREATE VIEW science_students AS
    SELECT sname, marks
    FROM student8
    WHERE course = 'Science';
    ```

#### Q10. Grant SELECT permission on the view from Q6 to a user called `faculty`.
*   **Solution Query:**
    ```sql
    GRANT SELECT ON high_scorers TO 'faculty'@'localhost';
    ```

### 🔹 Advanced Practice Exercises

#### Q11. Create a view that shows the top 2 students based on marks.
*   **Solution Query:**
    ```sql
    CREATE VIEW top_students AS
    SELECT *
    FROM student8
    ORDER BY marks DESC
    LIMIT 2;
    ```

#### Q12. Create a view that shows the count of students per course.
*   **Solution Query:**
    ```sql
    CREATE VIEW course_student_count AS
    SELECT course, COUNT(*) AS student_count
    FROM student8
    GROUP BY course;
    ```

#### Q13. Try inserting a new record into a view (check if it is allowed or not).
*   **Verification Statement:**
    ```sql
    INSERT INTO student_no_phone (sid, sname, course, marks)
    VALUES (6, 'David', 'English', 82);
    ```
    *   **Result:** This operation **succeeds** because `student_no_phone` is a simple view built on a single base table, and the excluded column (`phone`) can accept `NULL` values.

#### Q14. Create a view that joins students with a new table `faculty` (fields: `course`, `faculty_name`) to show course $\rightarrow$ faculty mappings.
*   **Solution Query:**
    ```sql
    -- Create and populate Faculty table first
    CREATE TABLE faculty (
        course VARCHAR(50) PRIMARY KEY,
        faculty_name VARCHAR(50)
    );
    
    INSERT INTO faculty VALUES
    ('Maths', 'Prof. Sharma'),
    ('Science', 'Prof. Verma'),
    ('English', 'Prof. Patel');
    
    -- Create the View with Join
    CREATE VIEW student_faculty_info AS
    SELECT s.sname, s.course, f.faculty_name
    FROM student8 s
    JOIN faculty f ON s.course = f.course;
    ```

#### Q15. Revoke permissions on the view `high_scorers` from the `faculty` user.
*   **Solution Query:**
    ```sql
    REVOKE SELECT ON high_scorers FROM 'faculty'@'localhost';
    ```
