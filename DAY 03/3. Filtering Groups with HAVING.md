# Day 03: Chapter 3 — Filtering Groups with HAVING

When working with summarized data, we often need to filter groups based on the calculated summary (e.g., *"Show me only products that have total sales above $50,000"*). In SQL, we use the **`HAVING`** clause for this purpose.

---

## 🎯 What is the `HAVING` Clause?

The `HAVING` clause is used to filter group summary rows created by `GROUP BY`. 

### Why can't we use `WHERE` for group summaries?
The SQL `WHERE` clause filters individual rows **before** they are grouped or aggregated. Because the aggregate values (like `SUM` or `COUNT`) do not exist yet when the `WHERE` clause runs, MySQL will throw an error if you try to use an aggregate function in `WHERE`.

*   *Error (Invalid):* `SELECT product FROM Sales WHERE SUM(price) > 50000 GROUP BY product;`
*   *Correct (Valid):* `SELECT product FROM Sales GROUP BY product HAVING SUM(price) > 50000;`

---

## 🔄 Difference Between `WHERE` and `HAVING`

| Feature | `WHERE` | `HAVING` |
| :--- | :--- | :--- |
| **Execution Phase** | Runs **before** data is grouped. | Runs **after** data is grouped and aggregated. |
| **Operates On** | Individual table rows. | Grouped rows (summaries). |
| **Aggregates Allowed?**| No (cannot use `COUNT`, `SUM`, etc. inside it). | Yes (can filter using `COUNT`, `SUM`, etc.). |
| **Performance** | Faster (reduces rows before processing). | Slower (runs after grouping all table rows). |

---

## 🔍 Examples using the `Sales` Table

We will use the following example table:
*   `Sales (id, customer_name, product, quantity, price, city)`

### Example 1: Products with total sales above 50,000
```sql
SELECT product, SUM(price * quantity) AS total_sales
FROM Sales
GROUP BY product
HAVING total_sales > 50000;
```
*   **Result**: Groups sales by `product`, calculates the total sales for each, and displays only the products whose total sales exceed 50,000 (e.g., Laptops).

### Example 2: Cities with more than 2 orders
```sql
SELECT city, COUNT(*) AS total_orders
FROM Sales
GROUP BY city
HAVING total_orders > 2;
```
*   **Result**: Groups orders by `city` and lists only cities where the order count is strictly greater than 2.

---

## 🏗️ Combining `WHERE`, `GROUP BY`, `HAVING`, and `ORDER BY`

A single query can combine all these clauses. The order of clauses in your SQL query must be:

1.  `SELECT`
2.  `FROM`
3.  `WHERE` (Filters raw rows)
4.  `GROUP BY` (Groups remaining rows)
5.  `HAVING` (Filters groups)
6.  `ORDER BY` (Sorts final outputs)

### Complete Example:
```sql
-- Find products sold in Delhi with average quantity sold > 1, sorted by avg quantity
SELECT product, AVG(quantity) AS avg_qty
FROM Sales
WHERE city = 'Delhi'          -- 1. Filter rows (Delhi only)
GROUP BY product              -- 2. Group by product
HAVING avg_qty > 1            -- 3. Filter groups (Avg quantity > 1)
ORDER BY avg_qty DESC;        -- 4. Sort results
```

### 🧭 Execution Order vs. Syntax Order
Although we write `SELECT` first, the database engine executes the clauses in this order:
`FROM` ➔ `WHERE` ➔ `GROUP BY` ➔ `HAVING` ➔ `SELECT` ➔ `ORDER BY`
This is why you can reference alias names in `HAVING` and `ORDER BY` in MySQL, but not in `WHERE`.
