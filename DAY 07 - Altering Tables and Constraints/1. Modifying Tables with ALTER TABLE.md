# Day 07: Chapter 1 — Modifying Tables with ALTER TABLE

In a software project's lifecycle, requirements change. You will frequently need to modify an existing table's schema (adding new columns, removing obsolete columns, or changing datatypes) without destroying the existing records. In SQL, this is handled using the **`ALTER TABLE`** statement.

---

## 1. Adding Columns (`ADD COLUMN`)

To add a new column to a table, use the `ADD` (or `ADD COLUMN`) keyword followed by the column definition.

### Basic Syntax
```sql
ALTER TABLE table_name
ADD COLUMN column_name data_type [constraints];
```

### Controlling Column Position
By default, MySQL appends new columns to the **end** of the table. You can control this position using `FIRST` or `AFTER`:

*   **Add at the very beginning:**
    ```sql
    ALTER TABLE Employees
    ADD COLUMN emp_code VARCHAR(10) FIRST;
    ```
*   **Add after a specific column:**
    ```sql
    ALTER TABLE Employees
    ADD COLUMN middle_name VARCHAR(50) AFTER first_name;
    ```

---

## 2. Dropping Columns (`DROP COLUMN`)

To remove a column and all of its stored data, use the `DROP` (or `DROP COLUMN`) keyword.

### Syntax
```sql
ALTER TABLE Employees
DROP COLUMN middle_name;
```

> [!CAUTION]
> Dropping a column is **irreversible**. All data stored in that column across all rows is deleted permanently. Ensure you have backed up the database or confirmed the column is no longer referenced by application code.

---

## 3. Modifying Columns (`MODIFY` vs. `CHANGE`)

To change a column's datatype, length, nullability, or default value, MySQL provides two methods:

### A. `MODIFY COLUMN`
Use `MODIFY` if you only want to change the datatype or constraints, **keeping the column name the same**.
```sql
-- Increase character limit and enforce NOT NULL
ALTER TABLE Employees
MODIFY COLUMN email VARCHAR(100) NOT NULL;
```

### B. `CHANGE COLUMN`
Use `CHANGE` if you want to **rename the column and change its datatype/constraints** at the same time. The syntax requires specifying both the *old* name and the *new* name.
```sql
-- Rename 'salary' to 'monthly_pay' and change datatype to DECIMAL
ALTER TABLE Employees
CHANGE COLUMN salary monthly_pay DECIMAL(10,2) NOT NULL;
```

---

## 4. Renaming Columns and Tables

### A. Renaming Columns (`RENAME COLUMN`)
If you only want to rename a column without changing its attributes, MySQL 8.0+ supports the `RENAME COLUMN` syntax:
```sql
ALTER TABLE Employees
RENAME COLUMN first_name TO given_name;
```

### B. Renaming Tables (`RENAME TO`)
To rename the entire table:
```sql
-- Method 1: Using ALTER TABLE
ALTER TABLE Employees
RENAME TO Staff;

-- Method 2: Using RENAME TABLE command
RENAME TABLE Staff TO Employees;
```

---

## ⚠️ Production Risks & Best Practices

Altering a table in a live production environment contains significant risks:

1.  **Table Locking**: In MySQL, running an `ALTER TABLE` statement on a large table (millions of rows) can lock the table, preventing other users from inserting or updating records, causing application timeouts.
2.  **Data Truncation**: If you shrink a column's width (e.g., converting `VARCHAR(100)` to `VARCHAR(20)`) or convert a string column to an integer, MySQL will throw truncation errors or discard text that exceeds the new limit.
3.  **Application Breaks**: Dropping or renaming a column will immediately crash any active application queries, APIs, or stored procedures that reference that column.
