# Day 05: Chapter 2 — Set Operators (UNION, INTERSECT, and EXCEPT)

**Set operators** are used to combine the result sets of two or more `SELECT` queries into a single output. 

Unlike **Joins** (which combine columns horizontally from different tables), **Set Operators** combine rows vertically (stacking the rows on top of each other).

```
          [ JOIN ]                            [ SET OPERATOR ]
   ┌─────────┬─────────┐                       ┌───────────────┐
   │ Table A │ Table B │                       │   Query A     │
   │ Cols    │ Cols    │                       ├───────────────┤
   └─────────┴─────────┘                       │   Query B     │
   (Horizontal combination)                    └───────────────┘
                                             (Vertical combination)
```

---

## 🔑 Crucial Rules for Set Operations

For any set operation to succeed, the queries must satisfy these requirements:
1.  **Column Count**: The number of columns in all `SELECT` statements must be **exactly the same**.
2.  **Compatibility**: The data types of columns in corresponding positions must be compatible.
3.  **Logical Order**: The columns should follow the same order in all queries to prevent logic errors (e.g., matching a name with an ID).

---

## 📊 Sample Datasets: `Customers` & `Suppliers`

We will use the following tables to illustrate set operations:

### `Customers` Table
| id | name | city |
| :--- | :--- | :--- |
| 1 | John | London |
| 2 | Alice | Paris |
| 3 | Raj | Delhi |
| 4 | Sara | Mumbai |

### `Suppliers` Table
| id | name | city |
| :--- | :--- | :--- |
| 2 | Supplier1 | Paris |
| 3 | Supplier2 | Delhi |
| 5 | Supplier3 | London |

## 1️⃣ UNION (Deduplicated Stacking)

The `UNION` operator combines the result sets of two or more `SELECT` queries and **automatically removes duplicate rows** (like applying `DISTINCT` across the entire merged set).

### Basic Fruit Example
```sql
SELECT 'Apple' AS fruit
UNION
SELECT 'Banana'
UNION
SELECT 'Apple';
```
*   **Result:**
    | fruit |
    | :--- |
    | Apple |
    | Banana |
*   *(The second 'Apple' is removed as a duplicate).*

### Table Example: Unique Cities
Find all unique cities where we have either a customer or a supplier.
```sql
SELECT city FROM Customers
UNION
SELECT city FROM Suppliers;
```
*   **Result:** London, Paris, Delhi, Mumbai. (Paris, Delhi, and London exist in both tables but appear only once in the output).

### Sorting Results
If you want to sort the combined results, place the `ORDER BY` clause at the very end of the final query:
```sql
SELECT city FROM Customers
UNION
SELECT city FROM Suppliers
ORDER BY city;
```

---

## 2️⃣ UNION ALL (Full Stacking with Duplicates)

The `UNION ALL` operator combines the results of multiple `SELECT` queries but **keeps all duplicates**. It does not perform any sorting or deduplication, making it significantly faster than `UNION`.

### Basic Fruit Example
```sql
SELECT 'Apple' AS fruit
UNION ALL
SELECT 'Banana'
UNION ALL
SELECT 'Apple';
```
*   **Result:** Apple, Banana, Apple (all records retained).

### Table Example: Combined Cities
```sql
SELECT city FROM Customers
UNION ALL
SELECT city FROM Suppliers;
```
*   **Result:** London, Paris, Delhi, Mumbai, Paris, Delhi, London (duplicates appear).

### Advanced: Counting Occurrences Across Tables
Because `UNION ALL` keeps duplicates, you can wrap it in an outer query to count occurrences:
```sql
SELECT city, COUNT(*) AS total_occurrences
FROM (
    SELECT city FROM Customers
    UNION ALL
    SELECT city FROM Suppliers
) AS all_cities
GROUP BY city;
```
*   **Result:** London (2), Paris (2), Delhi (2), Mumbai (1).

---

## ⚖️ UNION vs. UNION ALL

| Feature | `UNION` | `UNION ALL` |
| :--- | :--- | :--- |
| **Duplicates** | Removes duplicates | Keeps all duplicates |
| **Performance** | Slower (requires sorting and deduplication) | Faster (simply stacks rows) |
| **Use Case** | When you need a list of unique values. | When duplicates are required or performance is critical. |

---

## ⚠️ Valid vs. Invalid Set Configurations

### ✔ Valid: Stacking Different Columns Logically
You can select multiple columns as long as counts match.
```sql
SELECT name, city FROM Customers
UNION ALL
SELECT name, city FROM Suppliers;
```

### ❌ Invalid: Different Column Counts
```sql
-- This will throw a syntax error!
SELECT name FROM Customers
UNION
SELECT id, city FROM Suppliers;
```
`ERROR 1222 (21000): The used SELECT statements have a different number of columns`

### ❌ Invalid: Mismatched Column Meanings
This query will execute successfully because the columns match in count (2) and types, but the stacked data will make no sense:
```sql
SELECT id, name FROM Customers
UNION
SELECT name, city FROM Suppliers;
```
*   **Logical Error:** Supplier names will end up under the `id` column, and supplier cities will end up under the `name` column.

## 3️⃣ INTERSECT (Finding Common Rows)

The `INTERSECT` operator returns only the rows that are **common** to both queries (the intersection), automatically removing duplicates.

> [!NOTE]
> Standard MySQL (prior to version 8.0.31) does not support a native `INTERSECT` keyword. To achieve this in MySQL, you must use an `INNER JOIN` or `IN` clause.

### Emulating INTERSECT in MySQL

#### Example 1: Find common IDs in both Customers and Suppliers.
```sql
SELECT DISTINCT c.id, c.name, c.city
FROM Customers c
INNER JOIN Suppliers s ON c.id = s.id;
```
*   **Output:** 
    | id | name | city |
    | :--- | :--- | :--- |
    | 2 | Alice | Paris |
    | 3 | Raj | Delhi |

#### Example 2: Find common cities between Customers and Suppliers.
```sql
SELECT DISTINCT c.city
FROM Customers c
INNER JOIN Suppliers s ON c.city = s.city;
```
*   **Output:** Paris, Delhi, London.

---

## 4️⃣ EXCEPT (Subtracting Result Sets)

The `EXCEPT` (or `MINUS` in Oracle) operator returns rows from the first query that are **not present** in the second query. It automatically removes duplicates.

> [!NOTE]
> Standard MySQL (prior to version 8.0.31) does not support a native `EXCEPT` keyword. To achieve this in MySQL, we write a `LEFT JOIN` combined with an `IS NULL` check, or use a `NOT IN` subquery.

### Emulating EXCEPT in MySQL

#### Example: Find customers who do not exist in the Suppliers table (based on ID, Name, and City matches).
```sql
SELECT c.id, c.name, c.city
FROM Customers c
LEFT JOIN Suppliers s ON c.id = s.id AND c.name = s.name AND c.city = s.city
WHERE s.id IS NULL;
```
*   **Output:**
    | id | name | city |
    | :--- | :--- | :--- |
    | 1 | John | London |
    | 4 | Sara | Mumbai |
    | 2 | Alice | Paris |
    | 3 | Raj | Delhi |
*   *(Note: John and Sara exist in Customers but not in Suppliers. Alice and Raj have matching IDs, but their names and roles differ from the Suppliers table records).*
