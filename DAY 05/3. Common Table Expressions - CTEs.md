# Day 05: Chapter 3 — Common Table Expressions (CTEs)

A **Common Table Expression (CTE)** is a temporary, named result set that you can reference within a `SELECT`, `INSERT`, `UPDATE`, or `DELETE` statement. 

Defined using the **`WITH`** clause, CTEs exist only during the execution of a single query. They behave like temporary views that are created, queried, and discarded on the fly.

---

## 1. Syntax of a CTE

A CTE is defined at the beginning of a query using this syntax:

```sql
WITH CTE_Name AS (
    -- The subquery defining the CTE
    SELECT column1, column2
    FROM table_name
    WHERE condition
)
-- Main query referencing the CTE
SELECT *
FROM CTE_Name;
```

---

## 2. Advantages of CTEs over Subqueries

While CTEs and subqueries perform similar logical operations, CTEs offer major benefits:

1.  **Improved Readability**: Subqueries are written inline (often nested deep within the `FROM` or `WHERE` clauses), making them hard to read. CTEs are declared at the top of the query, making the code read sequentially from top to bottom.
2.  **Reusability**: You can reference the same CTE multiple times within the same main query (e.g., in joins or unions), avoiding duplicating the subquery code.
3.  **Modularity**: You can define multiple CTEs in a single statement, separating complex query logic into clean, separate blocks.
4.  **Recursion**: CTEs can reference themselves, allowing you to traverse hierarchical structures (like organization charts) using **recursive queries** (MySQL 8.0+).

---

## 3. Practical Examples

For these examples, we will reference the `Employees` table from Chapter 1.

### A. Example 1: Single CTE
Let's find all employees who earn more than the company's average salary.
```sql
WITH AverageSalaryCTE AS (
    SELECT AVG(salary) AS avg_sal FROM Employees
)
SELECT e.emp_name, e.salary
FROM Employees e
CROSS JOIN AverageSalaryCTE a
WHERE e.salary > a.avg_sal;
```

---

### B. Example 2: Defining Multiple CTEs
You can declare multiple CTEs by separating them with a comma. Later CTEs can reference earlier CTEs!

```sql
WITH DepartmentSalaries AS (
    -- Calculate total and average salaries per department
    SELECT dept, SUM(salary) AS total_sal, AVG(salary) AS avg_sal
    FROM Employees
    GROUP BY dept
),
HighestSpendingDept AS (
    -- Find the department with the highest total salary spend
    SELECT dept
    FROM DepartmentSalaries
    WHERE total_sal = (SELECT MAX(total_sal) FROM DepartmentSalaries)
)
-- Main query uses both CTEs to list employees in the highest spend department
SELECT e.emp_name, e.salary, e.dept
FROM Employees e
JOIN HighestSpendingDept h ON e.dept = h.dept;
```

---

### C. Example 3: Simple Recursive CTE (MySQL 8.0+)
A recursive CTE references itself. It is extremely useful for generating sequences or traversing hierarchical trees.

A recursive CTE consists of:
1.  **Anchor Member**: The base query that starts the recursion.
2.  **Recursive Member**: The query that references the CTE and adds rows.
3.  **Termination Condition**: A condition that stops the recursion when satisfied.

Here is a query to generate numbers from 1 to 5:
```sql
WITH RECURSIVE NumberSequence AS (
    -- Anchor Member: Start at 1
    SELECT 1 AS num
    
    UNION ALL
    
    -- Recursive Member: Add 1 to the previous value
    SELECT num + 1
    FROM NumberSequence
    WHERE num < 5 -- Termination Condition
)
SELECT num FROM NumberSequence;
```
*   **Output:** 1, 2, 3, 4, 5.
