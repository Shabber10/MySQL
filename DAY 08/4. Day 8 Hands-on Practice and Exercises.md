## 🟢 Part 1: Commit and Rollback Tasks

### Exercise 1: Rollback Verification
1.  Start a transaction.
2.  Deduct $200 from Alice's account (ID 1).
3.  Add $200 to Bob's account (ID 2).
4.  Roll back the transaction.
5.  Select balances to confirm no money moved.
*   **Queries:**
    ```sql
    START TRANSACTION;
    UPDATE Accounts SET balance = balance - 200.00 WHERE id = 1;
    UPDATE Accounts SET balance = balance + 200.00 WHERE id = 2;
    ROLLBACK;
    
    -- Verify balances:
    SELECT * FROM Accounts;
    ```
*   **Expected Balance Output:** Alice = 1000.00, Bob = 500.00.

## 🟡 Part 2: Savepoint Tasks

### Exercise 2: Granular Rollbacks
1.  Start a transaction.
2.  Add $100 to Alice's balance.
3.  Create a savepoint named `sp_alice_deposit`.
4.  Add $300 to Bob's balance.
5.  Roll back the transaction to the savepoint `sp_alice_deposit`.
6.  Commit the transaction.
7.  Select balances to confirm Alice's deposit was saved, but Bob's deposit was discarded.
*   **Queries:**
    ```sql
    START TRANSACTION;
    UPDATE Accounts SET balance = balance + 100.00 WHERE id = 1;
    SAVEPOINT sp_alice_deposit;
    UPDATE Accounts SET balance = balance + 300.00 WHERE id = 2;
    ROLLBACK TO SAVEPOINT sp_alice_deposit;
    COMMIT;
    
    -- Verify balances:
    SELECT * FROM Accounts;
    ```
*   **Expected Balance Output:** Alice = 1100.00, Bob = 500.00.

## 🔴 Part 3: Concurrency & Locking Simulation

To observe isolation levels, you must run two concurrent sessions in separate terminal windows (Session A and Session B). 

### Exercise 3: Witnessing a Dirty Read (READ UNCOMMITTED)

| Time | Session A (Terminal 1) | Session B (Terminal 2) |
