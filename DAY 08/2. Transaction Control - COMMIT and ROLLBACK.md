# Day 08: Chapter 2 — Transaction Control (COMMIT, ROLLBACK & SAVEPOINT)

To manage transaction states, SQL provides transaction control language (TCL) commands. These commands allow you to start transactions, finalize changes, discard modifications, or create checkpoints for granular rollbacks.

---

## 1. Core Transaction Control Commands

### A. Starting a Transaction
To tell MySQL that subsequent SQL queries must be treated as a single transaction block, use either:
```sql
START TRANSACTION;
-- or
BEGIN;
```

### B. Committing Changes (`COMMIT`)
Saves all changes made during the transaction permanently to the database. Once committed, the changes are visible to all other users and cannot be rolled back.
```sql
START TRANSACTION;
UPDATE Accounts SET balance = balance - 500 WHERE id = 1;
UPDATE Accounts SET balance = balance + 500 WHERE id = 2;
COMMIT; -- Finalizes the updates
```

### C. Rolling Back Changes (`ROLLBACK`)
Aborts the active transaction, discarding all SQL updates made since the transaction started.
```sql
START TRANSACTION;
UPDATE Accounts SET balance = balance - 500 WHERE id = 1;
-- System detects an error!
ROLLBACK; -- Restores balance to original values
```

---

## 2. Granular Controls: Savepoints

A **Savepoint** is a checkpoint within a transaction. It allows you to roll back a **portion** of the transaction's changes without discarding the entire block.

```
START TRANSACTION ────> Query 1 ────> SAVEPOINT A ────> Query 2 ────> ROLLBACK TO A ────> COMMIT
                                                            (Discards Query 2 only)
```

### Savepoint Commands

*   **Create a checkpoint:**
    ```sql
    SAVEPOINT checkpoint_name;
    ```
*   **Roll back to a checkpoint:**
    ```sql
    ROLLBACK TO SAVEPOINT checkpoint_name;
    ```
    *(Note: This discards only the updates made after the savepoint was created. The transaction remains open).*
*   **Remove a checkpoint:**
    ```sql
    RELEASE SAVEPOINT checkpoint_name;
    ```

---

## 3. Autocommit Mode

By default, MySQL runs in **Autocommit Mode** (`autocommit = 1`). In this mode, every single SQL statement is treated as its own transaction and is committed immediately upon execution.

*   **Turn off autocommit globally/session-wide:**
    ```sql
    SET autocommit = 0;
    -- or
    SET @@autocommit = 0;
    ```
    When autocommit is turned off, you must explicitly write `COMMIT` to save updates, otherwise they remain in memory and are discarded when the session closes.
*   **Turn on autocommit:**
    ```sql
    SET autocommit = 1;
    ```

## ⚠️ The DDL Implicit Commit Gotcha

A common pitfall in database development is assuming *every* SQL statement can be rolled back. 

In MySQL, running any **Data Definition Language (DDL)** query will **implicitly commit** your active transaction immediately. You cannot roll back a DDL statement, nor can you roll back DML statements executed before it in the same transaction!

### Commands that cause Implicit Commits:
- Schema changes: `CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`, `RENAME TABLE`, `TRUNCATE TABLE`.
- Database changes: `CREATE DATABASE`, `DROP DATABASE`.
- Permissions: `GRANT`, `REVOKE`.

### Example of the pitfall:
```sql
START TRANSACTION;
INSERT INTO Accounts (id, balance) VALUES (3, 1000.00); -- DML
ALTER TABLE Accounts ADD COLUMN status VARCHAR(10);     -- DDL (Implicitly Commits Transaction!)
ROLLBACK; -- ❌ This ROLLBACK does nothing! The insert was already committed by ALTER.
```
