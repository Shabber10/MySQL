# Day 04: Chapter 5 — Self and Cross Joins

In this chapter, we explore advanced join techniques used to solve specific relational data patterns: joining a table to itself (**Self Join**) and generating combinatorics (**Cross Join**).

---

## 1. Self Join

A **Self Join** is not a different type of join keyword; rather, it is any standard join (like `INNER JOIN` or `LEFT JOIN`) in which a table is joined with itself.

### Why join a table to itself?
A self join is used when a table contains a **unary relationship** (a relationship where a row references another row in the same table).

#### A. Real-World Example: Employee Organization Hierarchy
Imagine an `Employees` table where each employee has a `manager_id` that references the `emp_id` of their manager (who is also an employee in the same table).

##### `Employees` Table
| emp_id | name | role | manager_id |
| :--- | :--- | :--- | :--- |
| 1 | Alice | CEO | NULL |
| 2 | Bob | Manager | 1 |
| 3 | Charlie | Developer | 2 |
| 4 | David | Developer | 2 |

*   Alice is the CEO (no manager).
*   Bob reports to Alice (`manager_id` = 1).
*   Charlie and David report to Bob (`manager_id` = 2).

##### The Query (Table Aliasing is Mandatory)
Because we are querying the same table twice, we must assign unique aliases to differentiate the "Employee copy" from the "Manager copy" of the table:

```sql
SELECT 
    e.name AS Employee_Name, 
    e.role AS Employee_Role, 
    m.name AS Manager_Name
FROM Employees e
LEFT JOIN Employees m ON e.manager_id = m.emp_id;
```

##### Result Set
| Employee_Name | Employee_Role | Manager_Name |
| :--- | :--- | :--- |
| Alice | CEO | NULL |
| Bob | Manager | Alice |
| Charlie | Developer | Bob |
| David | Developer | Bob |

*   We use a `LEFT JOIN` so that Alice (who has no manager) is still included. If we had used an `INNER JOIN`, Alice would be excluded.

## 2. Cross Join

A **Cross Join** performs a **Cartesian Product** of two tables. It pairs every single row from the first table with every single row from the second table.

### Venn Diagram
```
     Table A            Table B
   ┌─────────┐        ┌─────────┐
   │  Row 1  │───────>│  Row A  │
   │         │──┐  ┌─>│  Row B  │
   │  Row 2  │  │  │  │         │
   └─────────┘  └──┼──└─────────┘
                └──┘
             CROSS JOIN
```

### Syntax
```sql
SELECT column_list
FROM table1
CROSS JOIN table2;
```
> [!NOTE]
> No `ON` or `USING` clause is used in a `CROSS JOIN` because there are no matching conditions.

---

### Real-World Example: Product Configurations
Imagine a custom bicycle shop that offers frames in different sizes and colors.

#### `Sizes` Table
| size |
| :--- |
| S |
| M |
| L |

#### `Colors` Table
| color |
| :--- |
| Red |
| Black |

#### The Query
```sql
SELECT s.size, c.color
FROM Sizes s
CROSS JOIN Colors c;
```

#### Result Set (3 × 2 = 6 Rows)
| size | color |
| :--- | :--- |
| S | Red |
| S | Black |
| M | Red |
| M | Black |
| L | Red |
| L | Black |

---

## ⚠️ Performance Warning: Exponential Row Growth
While cross joins are useful for generating matrix options, they represent a significant performance risk in production databases. 

If Table A has 10,000 rows and Table B has 10,000 rows, a `CROSS JOIN` will attempt to build and return a dataset containing **100,000,000 (100 million) rows**.

> [!CAUTION]
> In MySQL, if you write a standard `JOIN` statement and forget to write the `ON` or `USING` clause, MySQL defaults the query to a `CROSS JOIN`. Always double-check your join conditions to avoid crashing your server!

## 📝 Practice Exercises: Self Joins

To practice Self Joins, we use the following hierarchical `Employees` table:

### `Employees` Table
| emp_id | emp_name | manager_id |
| :--- | :--- | :--- |
| 1 | John | NULL |
| 2 | Alice | 1 |
| 3 | Bob | 1 |
| 4 | David | 2 |
| 5 | Emma | 2 |

---

### 🟢 Basic Level

#### Q1. Find each employee along with their manager's name.
*   **Query**:
    ```sql
    SELECT e.emp_name AS Employee, m.emp_name AS Manager
    FROM Employees e
    LEFT JOIN Employees m ON e.manager_id = m.emp_id;
    ```
*   **Expected Output**:
    | Employee | Manager |
    | :--- | :--- |
    | John | NULL |
    | Alice | John |
    | Bob | John |
    | David | Alice |
    | Emma | Alice |

#### Q2. Find employees who report directly to John.
*   **Query**:
    ```sql
    SELECT e.emp_name
    FROM Employees e
    JOIN Employees m ON e.manager_id = m.emp_id
    WHERE m.emp_name = 'John';
    ```
*   **Expected Output**:
    | emp_name |
    | :--- |
    | Alice |
    | Bob |

#### Q3. List employees who don't have any manager (top-level bosses).
*   **Query**:
    ```sql
    SELECT emp_name
    FROM Employees
    WHERE manager_id IS NULL;
    ```
*   **Expected Output**:
    | emp_name |
    | :--- |
    | John |

---

### 🟡 Medium Level

#### Q4. Find all managers who have at least one employee reporting to them.
*   **Query**:
    ```sql
    SELECT DISTINCT m.emp_name AS Manager
    FROM Employees e
    JOIN Employees m ON e.manager_id = m.emp_id;
    ```
*   **Expected Output**:
    | Manager |
    | :--- |
    | John |
    | Alice |

#### Q5. Find employees who share the same manager (colleagues under the same manager).
*   **Query**:
    ```sql
    SELECT e1.emp_name AS Employee1, e2.emp_name AS Employee2, m.emp_name AS Manager
    FROM Employees e1
    JOIN Employees e2 ON e1.manager_id = e2.manager_id AND e1.emp_id < e2.emp_id
    JOIN Employees m ON e1.manager_id = m.emp_id;
    ```
*   **Expected Output**:
    | Employee1 | Employee2 | Manager |
    | :--- | :--- | :--- |
    | Alice | Bob | John |
    | David | Emma | Alice |

#### Q6. Show all employees with their manager and manager's manager (grand boss).
*   **Query**:
    ```sql
    SELECT e.emp_name AS Employee,
           m.emp_name AS Manager,
           gm.emp_name AS Grand_Manager
    FROM Employees e
    LEFT JOIN Employees m ON e.manager_id = m.emp_id
    LEFT JOIN Employees gm ON m.manager_id = gm.emp_id;
    ```
*   **Expected Output**:
    | Employee | Manager | Grand_Manager |
    | :--- | :--- | :--- |
    | John | NULL | NULL |
    | Alice | John | NULL |
    | Bob | John | NULL |
    | David | Alice | John |
    | Emma | Alice | John |

### 🔴 Real-Time Case Scenarios

#### Q7. Find pairs of employees where one is the manager of the other.
*   **Query**:
    ```sql
    SELECT e.emp_name AS Employee, m.emp_name AS Manager
    FROM Employees e
    JOIN Employees m ON e.manager_id = m.emp_id;
    ```
*   **Expected Output**:
    | Employee | Manager |
    | :--- | :--- |
    | Alice | John |
    | Bob | John |
    | David | Alice |
    | Emma | Alice |

#### Q8. Find employees who are managers but also report to someone else.
*   **Query**:
    ```sql
    SELECT DISTINCT e.emp_name
    FROM Employees e
    WHERE e.emp_id IN (SELECT DISTINCT manager_id FROM Employees)
      AND e.manager_id IS NOT NULL;
    ```
*   **Expected Output**:
    | emp_name |
    | :--- |
    | Alice |
