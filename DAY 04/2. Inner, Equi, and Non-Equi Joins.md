# Day 04: Chapter 2 — Inner, Equi, and Non-Equi Joins

In this chapter, we explore how tables are matched based on comparison operators. We will cover the standard **Inner Join**, the common equality-based **Equi Join**, and the highly versatile **Non-Equi Join**.

---

## 1. The INNER JOIN

An **INNER JOIN** selects records that have matching values in **both** tables. If a row from either table cannot be matched, it is excluded from the result set.

### Venn Diagram
<img src="../assets/inner_join_venn.png" width="450" alt="INNER JOIN Venn Diagram">

### Basic Syntax
```sql
SELECT column_list
FROM table1
INNER JOIN table2 ON table1.common_column = table2.common_column;
```
*(Note: `INNER` is optional. Writing `JOIN` defaults to an `INNER JOIN` in MySQL).*

---

## 2. Equi Joins vs. Non-Equi Joins

While "Inner", "Left", and "Right" describe *which* unmatched rows to keep, **Equi** and **Non-Equi** describe *how* we match rows using comparison operators.

### A. Equi Join
An **Equi Join** is any join that uses the equality operator (`=`) in the join condition.

*   **Real-World Example**: Matching orders to the customers who placed them by checking if the IDs are equal.
*   **Query**:
    ```sql
    SELECT c.name, o.order_id
    FROM Customers c
    INNER JOIN Orders o ON c.customer_id = o.customer_id; -- Equality condition (=)
    ```
> [!NOTE]
> Almost 90% of the joins you write in daily development are **Inner Equi Joins**.

---

### B. Non-Equi Join
A **Non-Equi Join** is a join that uses any operator **other than equality** to combine rows. These operators include:
*   Comparison operators: `<`, `>`, `<=`, `>=`, `!=` (or `<>`)
*   Range operators: `BETWEEN ... AND ...`

#### Real-World Example: Salary Grades
Imagine we have an `Employees` table with their salaries, and a `SalaryGrades` table that defines salary brackets. There is no common ID between these tables, so we cannot perform an Equi Join. Instead, we match the salary to a grade bracket.

##### `Employees` Table
| emp_id | name | salary |
| :--- | :--- | :--- |
| 1 | Amit | 35000.00 |
| 2 | Sara | 60000.00 |
| 3 | John | 15000.00 |

##### `SalaryGrades` Table
| grade | min_salary | max_salary |
| :--- | :--- | :--- |
| Low | 10000.00 | 20000.00 |
| Mid | 20001.00 | 50000.00 |
| High | 50001.00 | 90000.00 |

##### The Non-Equi Join Query
We join using the `BETWEEN` operator:
```sql
SELECT e.name, e.salary, sg.grade
FROM Employees e
INNER JOIN SalaryGrades sg ON e.salary BETWEEN sg.min_salary AND sg.max_salary;
```

##### Result Set
| name | salary | grade |
| :--- | :--- | :--- |
| Amit | 35000.00 | Mid |
| Sara | 60000.00 | High |
| John | 15000.00 | Low |

## 3. Best Practices & Query Tips

### A. Table Aliases
Always alias your tables when joining to keep your queries readable:
```sql
SELECT c.name, o.order_id
FROM Customers c 
JOIN Orders o ON c.customer_id = o.customer_id;
```

### B. Resolving Column Ambiguity
If a column exists in both tables (like `customer_id`), you must prefix it with the table alias. Otherwise, MySQL throws:
`ERROR 1052 (23000): Column 'customer_id' in field list is ambiguous`

*   ❌ **Incorrect**: `SELECT customer_id FROM Customers c JOIN Orders o ON c.customer_id = o.customer_id;`
*   ✔ **Correct**: `SELECT c.customer_id FROM Customers c JOIN Orders o ON c.customer_id = o.customer_id;`

### C. The `USING` Clause
If the joining columns share the **exact same name**, you can write a cleaner query using `USING`:
```sql
SELECT c.name, o.order_id
FROM Customers c
JOIN Orders o USING (customer_id);
```
