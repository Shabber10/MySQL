# Day 1: Data Types in MySQL

In a relational database, every column in a table must have a specified **Data Type**. This determines what kind of data the column can store (e.g., text, numbers, dates) and how much space it takes up.

Choosing the correct data type is critical for performance, storage efficiency, and data integrity.

---

## 1. String / Text Data Types

Used to store letters, words, sentences, or alphanumeric codes (like ZIP codes or phone numbers).

| Data Type | Description | Usage Example |
| :--- | :--- | :--- |
| **`CHAR(size)`** | Fixed-length string. If a value is shorter than `size`, spaces are appended. Faster for fixed-length data (e.g., country codes like 'US', 'IN'). Range: 0 to 255. | `country_code CHAR(2)` |
| **`VARCHAR(size)`** | Variable-length string. Only occupies space equal to the actual text length + 1 or 2 bytes. Most common type for names, emails, descriptions. Max size: 65,535. | `email VARCHAR(255)` |
| **`TEXT`** | Stores long-form text data (up to 65,535 characters). Cannot have default values. | `blog_post TEXT` |

---

## 2. Numeric Data Types

Used for storing whole numbers, decimals, currency, and scientific values.

| Data Type | Description | Usage Example |
| :--- | :--- | :--- |
| **`INT`** | Standard integer. Stores whole numbers from approximately -2 billion to +2 billion. (Use `BIGINT` for larger values, or `TINYINT` for small values like 0-255). | `age INT` |
| **`DECIMAL(size, d)`** | Exact fixed-point numeric value. Ideal for financial/currency values where rounding errors are unacceptable. `size` is the total number of digits; `d` is the digits after the decimal. | `price DECIMAL(10, 2)` (e.g., 99999999.99) |
| **`FLOAT` / `DOUBLE`** | Floating-point (approximate value) numbers. Used for scientific calculations where exact decimal precision is not strictly required. | `latitude FLOAT` |

---

## 3. Date and Time Data Types

Used to store calendar dates, times, and timestamps.

| Data Type | Description | Format | Usage Example |
| :--- | :--- | :--- | :--- |
| **`DATE`** | Stores a date (Year, Month, Day). | `YYYY-MM-DD` | `birth_date DATE` |
| **`TIME`** | Stores a time value or duration. | `HH:MM:SS` | `duration TIME` |
| **`DATETIME`** | Stores a date and time combination. | `YYYY-MM-DD HH:MM:SS` | `created_at DATETIME` |
| **`TIMESTAMP`** | Similar to `DATETIME`, but stores UTC time and automatically converts based on time zone. Max range is up to year 2038. | `last_modified TIMESTAMP` |

---

## 4. Other Key Data Types

*   **`BOOLEAN` (or `BOOL`):** MySQL does not have a true boolean type. It treats `BOOLEAN` as a synonym for `TINYINT(1)`. `0` represents `FALSE`, and `1` (or any non-zero value) represents `TRUE`.
*   **`JSON`:** Allows storing raw JSON objects directly, and provides built-in functions to query JSON properties.

---

## Best Practices for Choosing Data Types:
1.  **Be conservative with sizes:** Don't use `VARCHAR(500)` when a name will never exceed `VARCHAR(50)`.
2.  **Use `DECIMAL` for money:** Never use `FLOAT` or `DOUBLE` for financial transactions due to floating-point rounding issues.
3.  **Choose integers for IDs:** Primary keys are usually `INT` or `BIGINT` (often set to `AUTO_INCREMENT`).
