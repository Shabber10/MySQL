# Day 10: Chapter 1 — Stored Procedures in MySQL

A **Stored Procedure** is a prepared batch of SQL statements that you save in the database system and execute whenever needed. Think of a stored procedure like a function or method in programming languages (Java, Python, C#), but executing directly inside the database engine.

---

## ⚙️ 1. What is a Delimiter in MySQL?

By default, MySQL uses a semicolon (`;`) as the delimiter to signify the end of an SQL statement. 

### Why do we need to change the delimiter?
When writing a stored procedure, the procedure body contains multiple SQL statements, each ending with a semicolon (`;`).

```sql
-- ❌ Incorrect without changing DELIMITER:
CREATE PROCEDURE insert_row()
BEGIN
    INSERT INTO cust VALUES (1, 'Rahul', 'Delhi'); -- MySQL sees ';' and thinks the query ends here!
    SELECT * FROM cust;
END;
```

When MySQL encounters the first `;` inside `BEGIN ... END`, it prematurely stops parsing the procedure definition and throws a syntax error.

### The Correct Way (`DELIMITER //`)
We temporarily change the delimiter to `//` or `$$` so MySQL reads the entire `BEGIN ... END` block as one single unit.

```sql
DELIMITER //

CREATE PROCEDURE insert_row()
BEGIN
    INSERT INTO cust VALUES (1, 'Rahul', 'Delhi');
    SELECT * FROM cust;
END //

DELIMITER ; -- Reset back to standard semicolon
```

## 🎯 2. Advantages & Disadvantages of Stored Procedures

| Feature | Normal SQL Query | Stored Procedure |
| :--- | :--- | :--- |
| **Best For** | One-off, simple queries | Repeated, complex business logic |
| **Performance** | Requires network transit for every query | Faster execution (runs directly on DB server) |
| **Security** | Requires direct table permissions | Can restrict table access and grant `EXECUTE` only |
| **Reusability** | Query written repeatedly in application code | Defined once, called anytime (`CALL procedure()`) |
| **Maintainability**| Requires updating multiple application files | Update logic in one central database location |

### Pros & Cons

#### ✅ Advantages:
1. **Reusability:** Write once, call anywhere via `CALL procedure_name();`.
2. **Better Performance:** Reduces network round-trips by executing multiple queries inside the server.
3. **Security:** Restrict direct access to tables (`GRANT EXECUTE ON PROCEDURE`).
4. **Encapsulation:** Groups complex multi-step operations (`INSERT`, `UPDATE`, `DELETE`) into clean routines.

#### ❌ Disadvantages:
1. **Harder to Debug:** Lacks advanced step-by-step debugging tools found in traditional IDEs.
2. **Database Vendor Lock-in:** Syntax varies between MySQL, Oracle, SQL Server, and PostgreSQL.
3. **Server Overload:** Heavy mathematical computations in stored procedures can strain CPU/RAM on the database server.

## 📥 3. Stored Procedure Parameters (`IN`, `OUT`, `INOUT`)

Stored procedures accept three types of parameters:

1. **`IN` (Input Parameter):** Passes a value into the procedure. The procedure can read it but cannot modify the caller's original variable. (Default type).
2. **`OUT` (Output Parameter):** Passes a value out of the procedure back to the caller.
3. **`INOUT` (Input/Output Parameter):** Passes an initial value into the procedure, allows modification inside the procedure, and returns the modified value back to the caller.

## 💻 4. Hands-on CRUD Operations with Stored Procedures

Consider a `cust` table with the following structure:

```sql
CREATE TABLE cust (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    city VARCHAR(50)
);

INSERT INTO cust VALUES
(1, 'Raju', 'Hyderabad'),
(2, 'Rajesh', 'Bengaluru'),
(3, 'Ram', 'Chennai'),
(4, 'Pooja', 'Amritsar');
```

### A. SELECT Operation (Get All Rows)
```sql
DELIMITER //
CREATE PROCEDURE GetAllCustomers()
BEGIN
   SELECT * FROM cust;
END //
DELIMITER ;

-- Execution:
CALL GetAllCustomers();
```

### B. SELECT Operation with `IN` Parameter (Get Row by ID)
```sql
DELIMITER //
CREATE PROCEDURE GetCustomerById(IN cust_id INT)
BEGIN
   SELECT * FROM cust WHERE id = cust_id;
END //
DELIMITER ;

-- Execution:
CALL GetCustomerById(2);
```

### C. INSERT Operation
```sql
DELIMITER //
CREATE PROCEDURE InsertCustomer(
    IN cust_id INT,
    IN cust_name VARCHAR(50),
    IN cust_city VARCHAR(50)
)
BEGIN
   INSERT INTO cust (id, name, city) VALUES (cust_id, cust_name, cust_city);
   SELECT 'Customer Inserted Successfully!' AS message;
END //
DELIMITER ;

-- Execution:
CALL InsertCustomer(5, 'Ravi', 'Delhi');
```

### D. UPDATE Operation
```sql
DELIMITER //
CREATE PROCEDURE UpdateCustomerCity(
    IN cust_id INT,
    IN new_city VARCHAR(50)
)
BEGIN
   UPDATE cust SET city = new_city WHERE id = cust_id;
   SELECT 'Customer Updated Successfully!' AS message;
END //
DELIMITER ;

-- Execution:
CALL UpdateCustomerCity(3, 'Pune');
```

### E. DELETE Operation
```sql
DELIMITER //
CREATE PROCEDURE DeleteCustomer(IN cust_id INT)
BEGIN
   DELETE FROM cust WHERE id = cust_id;
   SELECT 'Customer Deleted Successfully!' AS message;
END //
DELIMITER ;

-- Execution:
CALL DeleteCustomer(4);
```

### F. Combined Multi-step Procedure (Insert + Select)
```sql
DELIMITER //
CREATE PROCEDURE InsertAndShow(
    IN cust_id INT,
    IN cust_name VARCHAR(50),
    IN cust_city VARCHAR(50)
)
BEGIN
   INSERT INTO cust (id, name, city) VALUES (cust_id, cust_name, cust_city);
   SELECT * FROM cust;
END //
DELIMITER ;

-- Execution:
CALL InsertAndShow(6, 'Meena', 'Vizag');
```

### G. Output Parameter Example (`OUT`)
```sql
DELIMITER //
CREATE PROCEDURE GetCustomerCountByCity(
    IN p_city VARCHAR(50),
    OUT p_count INT
)
BEGIN
    SELECT COUNT(*) INTO p_count 
    FROM cust 
    WHERE city = p_city;
END //
DELIMITER ;

-- Execution:
CALL GetCustomerCountByCity('Hyderabad', @total);
SELECT @total AS total_in_hyd;
```

## 🔍 5. View vs. Stored Procedure

| Feature | View 👁️ | Stored Procedure ⚙️ |
| :--- | :--- | :--- |
| **Concept** | A saved virtual table based on a `SELECT` query | A mini-program containing executable SQL logic |
| **Data Modifications**| Primarily for reading; updates are restricted | Fully supports `INSERT`, `UPDATE`, `DELETE`, `SELECT` |
| **Parameters** | Does NOT accept parameters | Accepts `IN`, `OUT`, and `INOUT` parameters |
| **Logic Support** | Only `SELECT` statements (no procedural logic) | Supports loops (`WHILE`), branching (`IF/ELSE`), variables |
| **Execution** | Queried like a table: `SELECT * FROM view_name;` | Executed with `CALL procedure_name();` |

> 💡 **Analogy:**
> - **View:** A saved filter or bookmarked shortcut in Excel.
> - **Stored Procedure:** An automated Excel Macro script that performs calculations and updates multiple cells.
