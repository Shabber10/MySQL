# Day 10: Chapter 2 — User-Defined Functions (UDFs)

A **Stored Function** (or User-Defined Function - UDF) is a database object that takes zero or more input parameters, performs calculations, and **must return a single scalar value**.

Unlike Stored Procedures (which are executed using `CALL`), Stored Functions are used directly inside standard SQL expressions (such as `SELECT`, `WHERE`, and `ORDER BY`), exactly like built-in scalar functions (`ROUND()`, `UPPER()`, `CONCAT()`).

---

## 🆚 Stored Procedures vs. Stored Functions

| Feature | Stored Procedure | Stored Function |
| :--- | :--- | :--- |
| **Return Value** | Optional (can return zero, one, or multiple result sets/OUT parameters). | **Mandatory** (must return exactly one scalar value via `RETURN`). |
| **Execution Method** | Executed using `CALL ProcedureName()`. | Called inline within SQL statements (`SELECT FunctionName()`). |
| **Allowed Statements** | Can perform `INSERT`, `UPDATE`, `DELETE`, and `SELECT`. | Primarily used for calculations (`SELECT`). Cannot execute statements that modify table data in strict contexts. |
| **Parameters** | Supports `IN`, `OUT`, and `INOUT` parameters. | Supports **only `IN` parameters**. |
| **Control Flow** | Supports full transaction controls (`COMMIT`, `ROLLBACK`). | Cannot manage transactions (`COMMIT`/`ROLLBACK` not allowed). |

---

## 🛠️ Syntax of a Stored Function

```sql
DELIMITER //

CREATE FUNCTION function_name(param1 data_type, param2 data_type)
RETURNS return_data_type
[DETERMINISTIC | NOT DETERMINISTIC]
[READS SQL DATA | NO SQL]
BEGIN
    -- Declare local variables
    DECLARE result_var return_data_type;
    
    -- Execution logic
    SET result_var = ...;
    
    -- Return statement (Mandatory)
    RETURN result_var;
END //

DELIMITER ;
```

---

## 🔑 Function Deterministic Characteristics

When creating a function in MySQL, you must specify its deterministic characteristic so the optimizer knows how to handle caching and binary logging:

1. **`DETERMINISTIC`**: The function **always** returns the exact same result when given the same input parameters (e.g., calculating tax based on salary, or multiplying numbers).
2. **`NOT DETERMINISTIC`**: The function may return different results even with identical inputs (e.g., functions using `NOW()`, `CURDATE()`, or `RAND()`).
3. **`READS SQL DATA`**: The function reads data from database tables (via `SELECT`) but does not modify data.
4. **`NO SQL`**: The function contains no SQL statements at all (pure mathematical calculation).

## 💡 Practical Examples

### Example 1: Scalar Calculation Function (Calculate Total Price with Tax)

```sql
DELIMITER //

CREATE FUNCTION CalculateTax(price DECIMAL(10,2), tax_rate DECIMAL(5,2))
RETURNS DECIMAL(10,2)
DETERMINISTIC
NO SQL
BEGIN
    DECLARE total_price DECIMAL(10,2);
    SET total_price = price + (price * (tax_rate / 100));
    RETURN total_price;
END //

DELIMITER ;

-- Calling the function in a SELECT statement:
SELECT CalculateTax(100.00, 18.00) AS final_amount; -- Output: 118.00

-- Using the function on a table:
SELECT product_name, price, CalculateTax(price, 18.00) AS price_with_tax
FROM Products;
```

---

### Example 2: Reading Database Data Function (Customer Status Classifier)

```sql
DELIMITER //

CREATE FUNCTION GetCustomerCategory(p_cust_id INT)
RETURNS VARCHAR(20)
READS SQL DATA
BEGIN
    DECLARE total_spent DECIMAL(10,2);
    DECLARE category VARCHAR(20);
    
    -- Fetch total spending for customer
    SELECT IFNULL(SUM(amount), 0) INTO total_spent
    FROM Orders
    WHERE customer_id = p_cust_id;
    
    -- Conditional classification
    IF total_spent > 50000 THEN
        SET category = 'VIP Gold';
    ELSEIF total_spent > 10000 THEN
        SET category = 'Silver';
    ELSE
        SET category = 'Regular';
    END IF;
    
    RETURN category;
END //

DELIMITER ;

-- Using the function in queries:
SELECT customer_id, name, GetCustomerCategory(customer_id) AS customer_tier
FROM Customers;
```

## 📝 Managing Stored Functions

