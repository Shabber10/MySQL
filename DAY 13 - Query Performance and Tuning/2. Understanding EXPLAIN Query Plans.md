# Day 13: Chapter 2 — Understanding EXPLAIN Query Plans

The `EXPLAIN` statement is the most essential tool in a MySQL developer's toolkit. It shows the **execution plan** chosen by the MySQL Query Optimizer for a given `SELECT`, `UPDATE`, or `DELETE` statement.

---

## 🔍 1. Running EXPLAIN

To analyze a query, prepend `EXPLAIN` or `EXPLAIN ANALYZE` (MySQL 8.0+) to your statement:

```sql
EXPLAIN SELECT e.name, d.department_name
FROM Employees e
JOIN Departments d ON e.dept_id = d.id
WHERE e.salary > 50000;
```

---

## 📊 2. Key Output Columns in EXPLAIN

| Column | Description | Ideal Value / Goal |
| :--- | :--- | :--- |
| **`id`** | Sequential identifier of the query step | Numbers indicate execution order |
| **`select_type`** | Type of query (`SIMPLE`, `PRIMARY`, `SUBQUERY`, `DERIVED`) | `SIMPLE` is fastest |
| **`table`** | The table to which the row output refers | Target table being accessed |
| **`type`** | **Join Type (Access Mechanism)** | Aim for `const`, `eq_ref`, `ref`, `range`. Avoid `ALL` |
| **`possible_keys`**| Indexes MySQL could choose to use | Should list available indexes |
| **`key`** | **Index actually chosen by MySQL** | Should NOT be `NULL` |
| **`key_len`** | Length of the chosen key in bytes | Smaller keys require less memory |
| **`rows`** | **Estimated number of rows inspected** | Lower is better |
| **`filtered`** | Percentage of rows filtered by table condition | High percentage (100.00%) is best |
| **`Extra`** | Additional execution details | Avoid `Using filesort` and `Using temporary` |

---

## 🎯 3. Join Types (`type` Column): Best to Worst

```
 🟢 const / system  ➜  eq_ref  ➜  ref  ➜  range  ➜  index  ➜  ALL 🔴
    (Fastest: PK Lookup)                                 (Slowest: Full Scan)
```

1. **`const` / `system`:** Primary Key or Unique Index single row lookup. (Instant).
2. **`eq_ref`:** Primary key join lookup for each row from previous table.
3. **`ref`:** Index lookup matching non-unique index values.
4. **`range`:** Index range scan (e.g. using `>`, `<`, `BETWEEN`, `IN`).
5. **`index`:** Full Index Scan (scans entire index tree; better than full table scan).
6. **`ALL`:** **Full Table Scan.** Every single row on disk is read. *(Red flag 🚩 for large tables!)*

---

## 💡 4. Essential Query Tuning Best Practices

1. **Avoid `SELECT *`:** Query only necessary columns to enable **Covering Indexes** (`Using index`).
2. **Index Filtering & Join Columns:** Ensure columns used in `WHERE`, `JOIN ON`, `ORDER BY`, and `GROUP BY` are indexed.
3. **Avoid Functions on Indexed Columns:**
   * ❌ `WHERE YEAR(order_date) = 2026` (Index disabled)
   * ✅ `WHERE order_date >= '2026-01-01' AND order_date <= '2026-12-31'` (Index used!)
4. **Eliminate Filesort:** Match your composite index order with the `ORDER BY` clause.
