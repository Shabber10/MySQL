# Day 2: Dealing with Missing Data (NULL)

In database design, you will frequently encounter cases where a data value is unknown, blank, or not applicable. SQL represents this missing information using a special marker called **`NULL`**.

---

## 1. What is NULL?

`NULL` is **not** a value. 
*   It is **not** equal to the number `0`.
*   It is **not** equal to an empty string `""` or spaces `" "`.
*   It is simply a marker representing **missing, unknown, or unassigned data**.

*Analogy:* Imagine a paper questionnaire.
*   If someone writes `0` for their income, their income is known to be **zero dollars**.
*   If someone leaves the income field **completely blank**, their income is **unknown** (`NULL`).

---

## 2. Filtering NULL Values: The Common Mistake

Because `NULL` represents an unknown, you cannot compare it using standard arithmetic operators like `=` or `!=`. 

In SQL, any direct comparison with `NULL` yields `UNKNOWN` (neither True nor False).

*   `5 = NULL` ➡️ `UNKNOWN`
*   `NULL = NULL` ➡️ `UNKNOWN`

### ❌ The Wrong Way:
```sql
-- This will return 0 rows! You cannot check equality with NULL using =
SELECT first_name, email FROM employees
WHERE email = NULL; 
```

### ✅ The Correct Way: `IS NULL` and `IS NOT NULL`
To check for missing data, SQL provides the special comparison phrases: `IS NULL` and `IS NOT NULL`.

#### Finding rows with missing data:
```sql
-- Find employees who do not have an email address stored
SELECT first_name, email FROM employees
WHERE email IS NULL;
```

#### Finding rows with defined data:
```sql
-- Find employees who DO have an email address stored
SELECT first_name, email FROM employees
WHERE email IS NOT NULL;
```

---

## 3. Summary of Null Comparisons

| Comparison | Valid SQL | Result |
| :--- | :--- | :--- |
| `column = NULL` | ❌ No | Returns nothing (always resolves to NULL/unknown) |
| `column != NULL` | ❌ No | Returns nothing (always resolves to NULL/unknown) |
| `column IS NULL` | ✅ Yes | Returns rows where the value is missing/empty |
| `column IS NOT NULL` | ✅ Yes | Returns rows where a valid value exists |
