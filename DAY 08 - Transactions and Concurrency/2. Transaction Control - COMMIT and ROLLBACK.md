# Day 08: Chapter 2 — Transaction Control (COMMIT, ROLLBACK & SAVEPOINT)

To manage transaction states, SQL provides **Transaction Control Language (TCL)** commands. These commands allow you to define transaction boundaries, save changes permanently, discard modifications, or create checkpoints for granular rollbacks.

---

## 1. What is a Transaction?

A **Transaction** is a sequence of one or more SQL statements that are executed together as a single, logical unit of work. Think of it like a checklist of steps that must all complete successfully for the overall task to be correct.

### 🏦 Real-Life Example:
Sending money from Account A to Account B requires two operations:
1.  **Step 1:** Deduct ₹1000 from Account A.
2.  **Step 2:** Add ₹1000 to Account B.

These two statements belong to **one transaction** because they represent one business operation. If only one step happens (e.g., money is deducted from Account A but never reaches Account B), the data becomes incorrect and inconsistent.

---

## 2. Core Transaction Control Commands

MySQL provides the following commands to control transactions:

| Command | Purpose | Example |
| :--- | :--- | :--- |
| **`START TRANSACTION`** / **`BEGIN`** | Starts a new manual transaction | `START TRANSACTION;` |
| **`COMMIT`** | Saves all changes permanently to disk | `COMMIT;` |
| **`ROLLBACK`** | Undoes all changes made since the transaction started | `ROLLBACK;` |
| **`SAVEPOINT`** | Marks a specific point inside a transaction | `SAVEPOINT step1;` |
| **`ROLLBACK TO SAVEPOINT`** | Undoes changes made *after* the specified savepoint | `ROLLBACK TO SAVEPOINT step1;` |

---

## 3. How MySQL Executes a Transaction (Hands-on Walkthrough)

Let's create a database table and see how transactions behave during success and failure.

### 🛠 Database Schema Setup
Execute the following to create the `accounts` table and insert dummy accounts for **Rahul** and **Priya**:

```sql
CREATE DATABASE IF NOT EXISTS day8_practice;
USE day8_practice;

CREATE TABLE accounts (
    id INT PRIMARY KEY,
    name VARCHAR(30),
    balance DECIMAL(10,2)
);

INSERT INTO accounts VALUES
(1, 'Rahul', 10000.00),
(2, 'Priya', 5000.00);
```

#### Current Table State:
| id | name | balance |
| :--- | :--- | :--- |
| 1 | Rahul | 10000.00 |
| 2 | Priya | 5000.00 |

---

### Scenario A: A Successful Transaction (COMMIT)
Rahul sends ₹2000 to Priya.

```sql
-- 1. Start the transaction block
START TRANSACTION;

-- 2. Deduct ₹2000 from Rahul
UPDATE accounts
SET balance = balance - 2000
WHERE id = 1;

-- 3. Add ₹2000 to Priya
UPDATE accounts
SET balance = balance + 2000
WHERE id = 2;

-- 4. Commit the changes permanently to disk
COMMIT;
```

#### Post-Transaction Table State:
*   Rahul's Balance: **₹8000.00**
*   Priya's Balance: **₹7000.00**
*   *Result:* All changes are permanently saved.

---

### Scenario B: A Transaction Failure (ROLLBACK)
Rahul tries to send another ₹2000 to Priya, but a database error occurs during the second update.

```sql
-- 1. Start the transaction block
START TRANSACTION;

-- 2. Deduct ₹2000 from Rahul (Updates Rahul to ₹6000 in memory)
UPDATE accounts
SET balance = balance - 2000
WHERE id = 1;

-- 3. Simulate an error (Updating a non-existent table)
UPDATE wrong_table
SET balance = balance + 2000;
-- ❌ MySQL returns an error: "Table 'day8_practice.wrong_table' doesn't exist"

-- 4. Undo the transaction because something went wrong
ROLLBACK;
```

#### Post-Transaction Table State:
*   Rahul's Balance: **₹8000.00** (Restored from the Undo Log!)
*   Priya's Balance: **₹7000.00**
*   *Result:* The database reverts to the state before `START TRANSACTION`.

---

## ⚠️ Important Behavior Note
Many beginners believe that **"If any SQL statement inside a transaction fails, MySQL automatically rolls back the entire transaction."** 

> [!WARNING]
> **This is NOT true in MySQL.**
> If a statement fails (e.g., syntax error, column mismatch), the transaction **remains active**. You (or your application code) must explicitly check for errors and issue a `ROLLBACK` command; otherwise, subsequent commands can still be committed.

## 4. Autocommit Mode

By default, MySQL runs with **Autocommit Mode** enabled (`autocommit = 1` or `ON`). This means:
*   Every single SQL statement is treated as a separate transaction.
*   The statement is automatically committed immediately after execution without requiring an explicit `COMMIT;` statement.

### Check Current Autocommit Status:
```sql
SELECT @@autocommit;
-- Returns 1 (ON) or 0 (OFF)
```

### Turn Off Autocommit:
```sql
SET autocommit = 0;
```
Once autocommit is disabled, MySQL waits for you to explicitly issue a `COMMIT;` or `ROLLBACK;` statement to close the transaction block.

## 5. Granular Controls: Savepoints

A **Savepoint** is a checkpoint within a transaction. It allows you to roll back a **portion** of the transaction's changes without discarding the entire block.

```
START TRANSACTION ──> Update 1 ──> SAVEPOINT sp1 ──> Update 2 ──> ROLLBACK TO sp1 ──> COMMIT
                                                      (Discards Update 2 only)
```

### Savepoint Commands:
*   **Create a checkpoint:** `SAVEPOINT checkpoint_name;`
*   **Roll back to a checkpoint:** `ROLLBACK TO SAVEPOINT checkpoint_name;`
*   **Remove a checkpoint:** `RELEASE SAVEPOINT checkpoint_name;`

### 💻 Savepoint Example:
```sql
START TRANSACTION;

-- Step 1: Deduct ₹1000 from Rahul
UPDATE accounts SET balance = balance - 1000 WHERE id = 1;
SAVEPOINT step1;

-- Step 2: Add ₹1000 to Priya
UPDATE accounts SET balance = balance + 1000 WHERE id = 2;
SAVEPOINT step2;

-- Suppose you realize Step 2 was incorrect or failed:
ROLLBACK TO SAVEPOINT step1;

-- Commit the transaction (Only changes before step1 are saved)
COMMIT;
```

## 💾 Storage Engine Support (InnoDB vs. MyISAM)

Transactions and TCL commands work properly only when using a **transactional storage engine**.

*   ✅ **InnoDB:** MySQL's default engine. Supports transactions, savepoints, row-level locking, and crash recovery.
*   ❌ **MyISAM:** An older, non-transactional engine. If you run a `ROLLBACK;` after modifying a MyISAM table, **nothing is reverted** because changes are written directly and immediately to disk.

---

## ⚠️ DDL Implicit Commit Gotcha

Some SQL statements perform an **implicit commit** in MySQL. 

In MySQL, running any **Data Definition Language (DDL)** query will **implicitly commit** your active transaction immediately. You cannot roll back a DDL statement, nor can you roll back DML statements executed before it in the same transaction!

### Commands that cause Implicit Commits:
*   **Schema changes:** `CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`, `RENAME TABLE`, `TRUNCATE TABLE`.
*   **Database changes:** `CREATE DATABASE`, `DROP DATABASE`.
*   **Permissions:** `GRANT`, `REVOKE`.

### Example:
```sql
START TRANSACTION;
INSERT INTO accounts (id, name, balance) VALUES (3, 'Vikram', 1000.00); -- DML
ALTER TABLE accounts ADD COLUMN status VARCHAR(10);                     -- DDL (Implicitly Commits!)
ROLLBACK; -- ❌ This ROLLBACK does nothing! The insert was already committed by ALTER.
```

## 🧠 Interview Q&A Practice

### 1. What is a transaction?
**Answer:** A transaction is a sequence of one or more SQL statements treated as a single logical unit of work. Either all statements succeed and are saved (`COMMIT`), or none do (`ROLLBACK`).

### 2. Which commands are used to start a transaction in MySQL?
**Answer:** `START TRANSACTION;` or `BEGIN;`.

### 3. What does the COMMIT command do?
**Answer:** It permanently saves all changes made during the current active transaction to non-volatile storage (disk), making them visible to all other database users.

### 4. What does the ROLLBACK command do?
**Answer:** It undoes all changes made in the current transaction that have not yet been committed, restoring the database to the state it was in before the transaction started.

### 5. Does MySQL support transactions for all tables?
**Answer:** No, MySQL supports transactions only when using a transactional storage engine, such as the default **InnoDB**. Non-transactional engines like **MyISAM** do not support transactions.

### 6. Which MySQL storage engine should you use if your application requires transactions?
**Answer:** The **InnoDB** storage engine.

### 7. What happens if you run ROLLBACK on a MyISAM table?
**Answer:** Nothing. MyISAM does not support transactions, so all modifications are committed immediately and cannot be rolled back.

### 8. What is the default value of autocommit in MySQL and what does it mean?
**Answer:** The default value is `1` (ON). This means MySQL automatically commits every SQL statement immediately after it runs.

### 9. Can DDL statements (like CREATE TABLE or ALTER TABLE) be rolled back in a transaction?
**Answer:** No. In MySQL, DDL statements cause an **implicit commit**. They automatically commit the current transaction, so they cannot be rolled back.
