# Day 01: Creating Databases and Tables (DDL Operations)

In SQL, **DDL (Data Definition Language)** is used to define, modify, and delete the structure of database objects. Database objects include databases, tables, views, indexes, triggers, and stored procedures.

Remember the DDL commands using the mnemonic: **DR. CAT** 🐱 (**D**rop, **R**ename, **C**reate, **A**lter, **T**runcate).

---

## 1. CREATE Command

The `CREATE` command is used to set up new databases and tables.

### Manage Databases:
*   **Create Database:**
    ```sql
    CREATE DATABASE school_db;
    ```
*   **Show All Databases:**
    ```sql
    SHOW DATABASES;
    ```
*   **Select Database for Use:** Before creating tables, you must select the database:
    ```sql
    USE school_db;
    ```

### Create Tables with Constraints:
Tables store data in columns and rows. When creating a table, we specify columns, data types, and **Constraints** (integrity rules). 

To remember constraints, use the phrase **P.N.D.U.F.** (*"Please Never Drop Us, Friends"*):
*   **P** - **`PRIMARY KEY`**: Uniquely identifies each row. Must be unique and cannot be empty (NOT NULL).
*   **N** - **`NOT NULL`**: Prevents a column from having a `NULL` (empty) value.
*   **D** - **`DEFAULT`**: Automatically inserts a default value if no value is provided.
*   **U** - **`UNIQUE`**: Guarantees that all values in a column are different.
*   **F** - **`FOREIGN KEY`**: Establishes links between tables.

#### Table Creation Example:
```sql
CREATE TABLE students (
    student_id INT AUTO_INCREMENT PRIMARY KEY,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,
    enrollment_date DATE NOT NULL,
    status VARCHAR(20) DEFAULT 'Active'
);
```

### Inspecting Table Schema:
*   **Show Tables:** Lists all tables in the database.
    ```sql
    SHOW TABLES;
    ```
*   **Describe Table:** Shows details of columns, types, nullability, keys, and default values.
    ```sql
    DESCRIBE students; -- Or: DESC students;
    ```

## 2. Deep Dive: SQL Constraints (Primary Key & Foreign Key)

### A. Primary Key & AUTO_INCREMENT
A **Primary Key** is a column (or set of columns) that uniquely identifies each row in a table. It is a logical combination of `UNIQUE` and `NOT NULL`.

#### Properties:
*   Each table can have only **one** Primary Key.
*   Duplicates and `NULL` values are strictly prohibited.
*   **Composite Primary Key:** A single primary key composed of multiple columns.
    ```sql
    CREATE TABLE StudentCourses (
        student_id INT,
        course_id INT,
        PRIMARY KEY (student_id, course_id) -- Composite Key
    );
    ```

#### Managing Primary Keys via ALTER TABLE:
*   **Add Primary Key:**
    ```sql
    ALTER TABLE students ADD PRIMARY KEY (student_id);
    ```
*   **Drop Primary Key:**
    If the primary key has `AUTO_INCREMENT` enabled, you must **remove auto-increment first** before dropping the key:
    ```sql
    -- Step 1: Remove AUTO_INCREMENT
    ALTER TABLE students MODIFY student_id INT;
    -- Step 2: Drop the Primary Key
    ALTER TABLE students DROP PRIMARY KEY;
    ```

> [!IMPORTANT]
> **Primary Key vs. NOT NULL Column Constraints:**
> When you drop a Primary Key, the column remains `NOT NULL` (expected behavior in MySQL). If you want the column to allow null values, you must explicitly modify it:
> `ALTER TABLE students MODIFY student_id INT NULL;`

*   **Change AUTO_INCREMENT Start Value:** By default, auto-increment starts from 1. You can change the next generated value:
    ```sql
    ALTER TABLE students AUTO_INCREMENT = 100;
    ```

---

### B. Foreign Key & Referential Integrity
A **Foreign Key** is a column in a child table that refers to a Primary Key in a parent table. It enforces **Referential Integrity**—ensuring that a value in the child table must already exist in the parent table.

#### Rules for Foreign Keys:
1.  **Column Names:** Can be different (e.g., parent has `dept_id`, child has `department_id`).
2.  **Data Types:** Must be exactly the same or compatible (e.g., size, unsignedness).
3.  **NULL Values:** If a foreign key column is `NULL`, MySQL skips the check (representing "no relationship").

#### Cascading Actions (`ON DELETE` / `ON UPDATE`):
Define what happens in the child table when a parent row is deleted or updated:

*   **`CASCADE`**: Automatically deletes/updates child rows.
*   **`SET NULL`**: Sets the child foreign key column to `NULL` (column must allow `NULL`).
*   **`RESTRICT` / `NO ACTION`** (Default): Blocks the parent operation if child rows exist.

```sql
-- Parent Table
CREATE TABLE Departments (
    dept_id INT PRIMARY KEY,
    dept_name VARCHAR(50)
);

-- Child Table with Foreign Key Cascades
CREATE TABLE Employees (
    emp_id INT PRIMARY KEY AUTO_INCREMENT,
    emp_name VARCHAR(50),
    department_id INT,
    FOREIGN KEY (department_id) REFERENCES Departments(dept_id)
        ON UPDATE CASCADE
        ON DELETE CASCADE
);
```

#### Managing Foreign Keys via ALTER TABLE:
*   **Add Foreign Key:**
    ```sql
    ALTER TABLE Employees
    ADD CONSTRAINT fk_dept
    FOREIGN KEY (department_id) REFERENCES Departments(dept_id);
    ```
*   **Drop Foreign Key:**
    ```sql
    ALTER TABLE Employees DROP FOREIGN KEY fk_dept;
    ```

> [!NOTE]
> **Why does DESCRIBE still show `MUL` after dropping a Foreign Key?**
> MySQL automatically creates an index on a foreign key column. When you drop the constraint, the index remains. To remove `MUL` from the `Key` column in `DESCRIBE`, you must drop the index:
> `ALTER TABLE Employees DROP INDEX department_id;`

## 3. ALTER Command

The `ALTER` command is used to modify the structure of an existing table without deleting it.

### A. Add a New Column:
```sql
ALTER TABLE students
ADD city VARCHAR(30);
```

### B. Modify Column Datatype:
Changes the datatype or size of an existing column:
```sql
ALTER TABLE students
MODIFY city CHAR(50);
```

### C. Change Column Name:
Renames a column and allows changing its datatype at the same time:
```sql
ALTER TABLE students
CHANGE city scity CHAR(30);
```

### D. Drop a Column:
Permanently removes a column from the table:
```sql
ALTER TABLE students
DROP COLUMN scity;
```

### E. Add Multiple Columns:
```sql
ALTER TABLE students
ADD email_backup VARCHAR(50),
ADD phone BIGINT;
```

### F. Drop Multiple Columns:
```sql
ALTER TABLE students
DROP COLUMN email_backup,
DROP COLUMN phone;
```

### G. Rename Table (via ALTER):
```sql
ALTER TABLE students
RENAME TO student_records;
```

---

## 4. RENAME Command

The `RENAME` command is a dedicated DDL statement used to rename an existing table.
```sql
RENAME TABLE student_records TO students;
```
*Note: Both `ALTER TABLE ... RENAME TO` and `RENAME TABLE` achieve the same result. `RENAME TABLE` is simply a standalone utility command.*

---

## 5. DROP and TRUNCATE Commands

### DROP Table vs. DROP Database:
`DROP` completely deletes the table/database along with its structure and all records permanently.
```sql
DROP TABLE students;
DROP DATABASE school_db;
```

### TRUNCATE Table:
`TRUNCATE` deletes all records inside a table, but keeps the table structure (columns and constraints) intact for future data.
```sql
TRUNCATE TABLE students;
```

## 6. Advanced Table Creation Techniques

### A. Creating One Table from Another (CTAS - `CREATE TABLE ... AS SELECT`)
You can create a new table based on the structure and data of an existing table using `CREATE TABLE ... AS SELECT`.

```sql
-- 1. Copy both structure AND data:
CREATE TABLE students_backup AS
SELECT * FROM students;

-- 2. Copy selected columns only:
CREATE TABLE student_basic AS
SELECT student_id, first_name, email FROM students;
```

### B. Copying Table Structure Only (`WHERE 1=0`)
If you want to create an empty duplicate table with the exact same column definitions but **no data rows**, use an always-false condition (`WHERE 1=0`):

```sql
CREATE TABLE empty_student_structure AS
SELECT * FROM students WHERE 1=0;
```

## 7. Generated Columns (Computed Columns)

A **Generated Column** (or Computed Column) is a column whose value is calculated automatically from other columns in the same row. You do not manually insert values into a generated column.

### Syntax & Example:
```sql
CREATE TABLE products (
    product_id INT PRIMARY KEY AUTO_INCREMENT,
    product_name VARCHAR(50) NOT NULL,
    unit_price DECIMAL(10,2) NOT NULL,
    quantity INT NOT NULL,
    total_price DECIMAL(10,2) GENERATED ALWAYS AS (unit_price * quantity) STORED
);

-- Insert data (do NOT specify total_price):
INSERT INTO products (product_name, unit_price, quantity) 
VALUES ('Apple', 20.00, 2);

-- Total price is calculated automatically (20.00 * 2 = 40.00):
SELECT * FROM products;

-- Updating quantity automatically recalculates total_price:
UPDATE products SET quantity = 5 WHERE product_id = 1;
-- total_price automatically updates to 100.00!
```

> 📌 **`STORED` vs `VIRTUAL` Generated Columns:**
> * **`STORED`**: The computed value is calculated and written to disk when rows are inserted or updated. Faster reads.
> * **`VIRTUAL`** (Default): The value is calculated on-the-fly whenever the row is queried. Uses less disk space.
