# Day 02: Advanced Filtering with WHERE

Yesterday, you learned the basic `SELECT` statement and the `WHERE` clause. Today, we will dive deeper into filtering rows using comparison operators, combining multiple conditions with logical operators (`AND`, `OR`, `NOT`), and controlling logic priority.

---

## 1. Comparison Operators

In MySQL, comparison operators are used inside the `WHERE` clause to filter rows based on specific conditions.

| Operator | Description | Example |
| :---: | :--- | :--- |
| **`=`** | Equal to | `WHERE department = 'HR'` |
| **`!=`** or **`<>`** | Not equal to | `WHERE status != 'Terminated'` |
| **`<`** | Less than | `WHERE salary < 50000.00` |
| **`>`** | Greater than | `WHERE age > 18` |
| **`<=`** | Less than or equal to | `WHERE join_date <= '2026-01-01'` |
| **`>=`** | Greater than or equal to | `WHERE stock_count >= 100` |

---

## 2. Logical Operators: AND, OR, and NOT

To filter data based on more than one condition, we use logical operators to combine filters.

### A. The `AND` Operator (All conditions must be True)
Retrieves a row only if **every** condition separated by `AND` is met.
```sql
-- Find employees who work in IT and make more than $70,000
SELECT employee_id, first_name, department, salary 
FROM employees
WHERE department = 'IT' AND salary > 70000.00;
```

### B. The `OR` Operator (At least one condition must be True)
Retrieves a row if **any** of the conditions separated by `OR` are met.
```sql
-- Find employees who work in either HR or Marketing
SELECT employee_id, first_name, department 
FROM employees
WHERE department = 'HR' OR department = 'Marketing';
```

### C. The `NOT` Operator (Reverses the condition)
Retrieves rows where the condition is **not** true.
```sql
-- Find employees who do NOT work in Sales
SELECT employee_id, first_name, department 
FROM employees
WHERE NOT department = 'Sales';
```

## 4. Arithmetic & Assignment Operators

### A. Arithmetic Operators (`+`, `-`, `*`, `/`, `%` or `MOD`)
Arithmetic operators perform mathematical calculations directly inside `SELECT` queries or `WHERE` filters.

| Operator | Description | Example SQL | Output |
| :---: | :--- | :--- | :--- |
| **`+`** | Addition | `SELECT 10 + 5;` | `15` |
| **`-`** | Subtraction | `SELECT 10 - 5;` | `5` |
| **`*`** | Multiplication | `SELECT 10 * 5;` | `50` |
| **`/`** | Division | `SELECT 10 / 5;` | `2.0000` |
| **`%`** / `MOD` | Modulus (Remainder) | `SELECT 10 % 3;` | `1` |

```sql
-- Calculate a 10% bonus for employees making over $50,000:
SELECT first_name, salary, (salary * 0.10) AS bonus, (salary * 1.10) AS total_pay
FROM employees
WHERE salary > 50000.00;
```

### B. Logical `XOR` Operator (Exclusive OR)
Returns `TRUE` if **exactly one** condition is true. If both conditions are true (or both are false), it returns `FALSE`.

```sql
-- Find employees who get EITHER a 10% bonus OR a pension plan, BUT NOT BOTH:
SELECT first_name, has_bonus, has_pension
FROM employees
WHERE has_bonus = 1 XOR has_pension = 1;
```

### C. Assignment Operators (`=`, `:=`)
Used to declare and assign values to MySQL user-defined session variables.
*   `SET @var = 10;`
*   `SELECT @var := 10;`

```sql
-- Set a variable and use it inside a query filter:
SET @target_dept = 'IT';
SELECT * FROM employees WHERE department = @target_dept;
```

## 5. Bitwise Operators (Low-Level Bit Manipulation)

**Bitwise operators** operate directly on individual bits (`0`s and `1`s) of integer values.

| Operator | Description | Example SQL | Binary Logic | Result |
| :---: | :--- | :--- | :--- | :---: |
| **`&`** | Bitwise AND | `SELECT 5 & 3;` | `0101 & 0011` | `1` (`0001`) |
| **`\|`** | Bitwise OR | `SELECT 5 \| 3;` | `0101 \| 0011` | `7` (`0111`) |
| **`^`** | Bitwise XOR | `SELECT 5 ^ 3;` | `0101 ^ 0011` | `6` (`0110`) |
| **`~`** | Bitwise Inversion (NOT) | `SELECT ~1;` | Inverts all bits | Bigint complement |
| **`<<`** | Left Bit Shift | `SELECT 5 << 1;` | Shifts bits left (multiplies by 2) | `10` |
| **`>>`** | Right Bit Shift | `SELECT 5 >> 1;` | Shifts bits right (divides by 2) | `2` |

> 🧠 **What are "Low-Level" Operations?**
> * **High-Level Operations:** Business-focused queries like filtering customer orders, calculating salaries, or grouping sales (`SELECT`, `WHERE`, `JOIN`).
> * **Low-Level Operations:** Operations working close to hardware, memory, or binary bits (`0`s and `1`s).
> 
> **Real-World Examples of Bitwise Operations:**
> 1. **Linux File Permissions:** Read (4 = `100`), Write (2 = `010`), Execute (1 = `001`). Read + Write = `4 | 2 = 6` (`110`).
> 2. **Hardware / Sensor Flags:** Using bits in integer flags to represent ON/OFF states (e.g. Bit 0 = LED, Bit 1 = Motor).
> 3. **Fast Multiplication / Division:** `5 << 1` multiplies 5 by 2 (`10`), while `20 >> 2` divides 20 by 4 (`5`).
