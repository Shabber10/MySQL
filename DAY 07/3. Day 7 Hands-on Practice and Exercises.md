# Day 07: Chapter 3 — Hands-on Practice & Exercises

This guide contains step-by-step practice tasks designed to test your ability to modify database schemas and manage constraints.

---

## 📊 Practice Scenario: Legacy Staff Restructuring

A business is migrating its legacy HR system. The initial database contains an unconstrained, loosely-typed `LegacyStaff` table:

```sql
CREATE TABLE LegacyStaff (
    id INT,
    name VARCHAR(30),
    salary DECIMAL(10,2)
);
```

You are tasked with applying new data integrity guidelines by altering the table structure.

---

### Task 1: Rename the Table
Rename the table from `LegacyStaff` to `StaffDetails`.
*   **Query:**
    ```sql
    RENAME TABLE LegacyStaff TO StaffDetails;
    ```

---

### Task 2: Make the ID column a Primary Key
Before adding a Primary Key, the column must be defined as `NOT NULL`.
*   **Step 2a: Modify the column to be NOT NULL:**
    ```sql
    ALTER TABLE StaffDetails
    MODIFY COLUMN id INT NOT NULL;
    ```
*   **Step 2b: Add the Primary Key constraint:**
    ```sql
    ALTER TABLE StaffDetails
    ADD PRIMARY KEY (id);
    ```

---

### Task 3: Add a new Email column
Add a column named `email` (data type `VARCHAR(80) NOT NULL`) positioned immediately after the `name` column.
*   **Query:**
    ```sql
    ALTER TABLE StaffDetails
    ADD COLUMN email VARCHAR(80) NOT NULL AFTER name;
    ```

---

### Task 4: Add a Unique constraint to Email
Add a Unique constraint named `uq_staff_email` to the `email` column to prevent duplicate accounts.
*   **Query:**
    ```sql
    ALTER TABLE StaffDetails
    ADD CONSTRAINT uq_staff_email UNIQUE (email);
    ```

---

### Task 5: Add a Check constraint to Salary
Add a check constraint named `chk_min_salary` ensuring that no employee receives a salary less than `1000.00`.
*   **Query:**
    ```sql
    ALTER TABLE StaffDetails
    ADD CONSTRAINT chk_min_salary CHECK (salary >= 1000.00);
    ```

---

### Task 6: Drop the Unique constraint on Email
To reverse Task 4, drop the unique constraint from the `email` column. Recall that in MySQL, unique constraints are dropped using their index name.
*   **Query:**
    ```sql
    ALTER TABLE StaffDetails
    DROP INDEX uq_staff_email;
    ```

---

## 🔍 Validation Queries
After executing the tasks, you can inspect your changes:

*   **View table structure details:**
    ```sql
    DESCRIBE StaffDetails;
    ```
*   **View active constraints and keys:**
    ```sql
    SHOW CREATE TABLE StaffDetails;
    ```
