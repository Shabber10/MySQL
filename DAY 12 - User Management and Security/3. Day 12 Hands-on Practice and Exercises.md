# Day 12: Chapter 3 — Hands-on Practice and Exercises

This guide contains the step-by-step SQL script to practice the user management and privilege workflow using a real-world College Administration scenario (Root $\rightarrow$ Admin $\rightarrow$ Faculty).

---

## 🛠️ Step-by-Step Scenario Practice

### Step 0: Initial Database & Table Setup (Logged in as `root`)
First, create the sample database and base table containing sensitive student information.

```sql
-- Create database
CREATE DATABASE college;
USE college;

-- Create student table
CREATE TABLE student (
    sid INT PRIMARY KEY,
    sname VARCHAR(50),
    course VARCHAR(50),
    marks INT,
    phone VARCHAR(15),
    address VARCHAR(100)
);

-- Insert sample records
INSERT INTO student VALUES
(1, 'Alice', 'Math', 85, '9876543210', 'Delhi'),
(2, 'Bob', 'Science', 90, '9123456780', 'Mumbai'),
(3, 'Charlie', 'History', 78, '9988776655', 'Chennai');
```

---

### Step 1: Root Creates the HOD Admin
The root user (Principal) creates the HOD user and grants them all privileges on the database with the grant option.

```sql
-- Root creates HOD user
CREATE USER 'admin'@'localhost' IDENTIFIED BY 'admin123';

-- Root grants all privileges + WITH GRANT OPTION to Admin
GRANT ALL PRIVILEGES ON college.* TO 'admin'@'localhost' WITH GRANT OPTION;
```

---

### Step 2: HOD Admin Creates the Faculty User
*Now, open a new connection and log in as user `admin` (password: `admin123`).*

```sql
-- Admin creates faculty user
CREATE USER 'faculty'@'localhost' IDENTIFIED BY 'faculty123';
```

---

### Step 3: HOD Admin Creates a Safe View for Faculty
The Admin (HOD) wants to allow the Faculty (Teacher) to see student details, but must hide sensitive information like phone numbers and home addresses.

```sql
-- Admin creates a secure view
USE college;

CREATE VIEW student_public AS
SELECT sid, sname, course, marks
FROM student;
```

---

### Step 4: HOD Admin Grants View Access to Faculty
The Admin grants SELECT privileges on the safe view, but not on the base table.

```sql
-- Admin grants SELECT privilege on the view to faculty
GRANT SELECT ON college.student_public TO 'faculty'@'localhost';
```

#### Verification (Logged in as `faculty` / password: `faculty123`):
```sql
-- This query will WORK successfully:
SELECT * FROM college.student_public;

-- This query will FAIL with 'Access Denied' error:
SELECT * FROM college.student;
```

---

### Step 5: HOD Admin Revokes Access (If needed)
If the faculty user should no longer have access, the Admin can revoke the privilege.

```sql
-- Admin revokes SELECT privilege
REVOKE SELECT ON college.student_public FROM 'faculty'@'localhost';
```

#### Verification (Logged in as `faculty`):
```sql
-- This query will now FAIL with 'Access Denied' error:
SELECT * FROM college.student_public;
```

## 📝 Practice Exercises

### Exercise 1: User Verification
1.  Log in as `root`.
2.  Write a query to display all users in the system and verify `admin` and `faculty` exist.
3.  Write the statement to delete only the `faculty` user.

### Exercise 2: Privilege Restricting
1.  Log in as `admin`.
2.  Grant both `SELECT` and `INSERT` privileges on the `student_public` view to the `faculty` user.
3.  Log in as `faculty`. Verify that you can insert a new student record using:
    ```sql
    INSERT INTO college.student_public (sid, sname, course, marks)
    VALUES (4, 'David', 'English', 82);
    ```
4.  Log in as `faculty`. Try updating a student's marks:
    ```sql
    UPDATE college.student_public SET marks = 95 WHERE sid = 1;
    ```
    *Explain why this command fails.* (Answer: Faculty was only granted `SELECT` and `INSERT`, not `UPDATE`).
