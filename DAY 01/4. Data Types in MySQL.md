# Day 01: Data Types in MySQL

In a relational database, every column in a table must have a specified **Data Type**. The data type tells the database what kind of values can be stored in that column (numbers, text, binary, dates), how much storage space to allocate, and what operations can be performed on the data.

MySQL data types are broadly divided into four main categories:
1.  **Numeric Types**
2.  **Character (Text) Types**
3.  **Binary Types**
4.  **Date and Time Types**

---

## 1. Numeric Data Types

Numeric types are split based on whether they store exact numbers or approximate floating-point values.

```
Numeric Types
│
├── Exact Numeric (Integers, Decimals, Bits)
│    ├── INT / INTEGER
│    ├── SMALLINT
│    ├── BIGINT
│    ├── DECIMAL / NUMERIC
│    └── BIT
│
└── Approximate Numeric (Floating points)
     ├── FLOAT
     ├── REAL
     └── DOUBLE PRECISION
```

### Exact Numeric Types (No rounding errors)
*   **`INT` or `INTEGER` (4 Bytes):** Stores standard whole numbers from approximately -2 billion to +2 billion.
*   **`SMALLINT` (2 Bytes):** Stores small whole numbers from -32,768 to 32,767.
*   **`BIGINT` (8 Bytes):** Stores extremely large whole numbers (e.g., global phone numbers, transaction IDs).
*   **`DECIMAL(p, s)` or `NUMERIC(p, s)`:** Used for fixed-point numbers. Essential for financial and currency data where rounding errors are unacceptable.
    *   `p` (Precision) = Total number of digits stored (both left and right of the decimal point).
    *   `s` (Scale) = Number of digits to the right of the decimal point.
    *   *Example:* `DECIMAL(5, 2)` can store values from `-999.99` to `999.99`.
*   **`BIT` (1 Bit):** Stores boolean values (`0` for False, `1` for True).

### Approximate Numeric Types (Floating-point)
*   **`FLOAT` / `REAL`:** Approximate decimal numbers with floating-point limits. Used in scientific calculations.
*   **`DOUBLE PRECISION`:** Higher-precision floating-point numbers.

## 2. Character vs. Binary Data Types

### Character Types (Text Storage)

*   **`CHAR(n)` (Fixed Length):** Always stores exactly `n` characters. If the text is shorter than `n`, MySQL pads the right side with spaces.
    *   *Best for:* Fixed-size codes (e.g., Country codes like `IND`/`USA`, Gender `M`/`F`, or Pin Codes).
*   **`VARCHAR(n)` (Variable Length):** Stores text up to `n` characters. It only uses the storage space of the actual text inserted (plus 1 or 2 bytes for length tracking).
    *   *Best for:* Variable-size text (e.g., Names, emails, addresses).

#### Difference Table:
| Feature | CHAR | VARCHAR |
| :--- | :--- | :--- |
| **Storage** | Fixed-length (pads spaces) | Variable-length (no padding) |
| **Performance** | Slightly faster for fixed-size data | Slightly slower (must calculate length) |
| **Best For** | Identical length strings (`CHAR(2)` for 'IN', 'US') | Diverse length strings (names, emails) |

#### Demonstrating the Padding Difference:
If we create a table with `CHAR(5)` and `VARCHAR(5)` and insert the word `'Cat'`:
*   `CHAR(5)` stores: `'Cat  '` (3 characters + 2 padded spaces, Length = 5)
*   `VARCHAR(5)` stores: `'Cat'` (3 characters, no padding, Length = 3)

---

### Binary Data Types (Byte Storage)

Binary types store raw sequences of bytes (0s and 1s) rather than readable text. They are used for storing images, audio files, PDFs, hashes, or encryption keys.

*   **`BINARY(n)` (Fixed Length):** Stores exactly `n` bytes. Pads with zero bytes (`0x00`) if the data is smaller.
*   **`VARBINARY(n)` (Variable Length):** Stores up to `n` bytes without padding.

```
Character & Binary Types
│
├── Character Types
│    ├── CHAR(n)    → Fixed length (space padding)
│    └── VARCHAR(n) → Variable length (no padding)
│
└── Binary Types
     ├── BINARY(n)    → Fixed length (zero byte padding)
     └── VARBINARY(n) → Variable length (no padding)
```

## 3. Date and Time Data Types

Used to record calendar dates and clock times:

| Data Type | Format | Range | Best Use |
| :--- | :--- | :--- | :--- |
| **`DATE`** | `YYYY-MM-DD` | `1000-01-01` to `9999-12-31` | Birthdays, hiring dates, invoice dates |
| **`TIME`** | `HH:MM:SS` | `-838:59:59` to `838:59:59` | Durations, business opening/closing hours |
| **`DATETIME`** | `YYYY-MM-DD HH:MM:SS` | `1000-01-01` to `9999-12-31` | Audit records (static timestamps) |
| **`TIMESTAMP`** | `YYYY-MM-DD HH:MM:SS` | `1970-01-01` to `2038-01-19` | Tracking when records are created/updated (auto-converts to UTC) |
| **`YEAR`** | `YYYY` | `1901` to `2155` | Storing graduation year, model release year |

### Automatic Timestamp Example:
You can configure a `TIMESTAMP` column to automatically stamp the current time whenever a row is inserted:
```sql
CREATE TABLE logs (
    log_id INT AUTO_INCREMENT PRIMARY KEY,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```
