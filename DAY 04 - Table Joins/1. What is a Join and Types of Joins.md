# Day 04: Chapter 1 — What is a Join & Types of Joins

In normalized relational databases, data is split across multiple tables to eliminate redundancy. When we need to answer complex business questions, we must combine these tables. This process is called **joining**.

---

## 1. Definition of a Join

A **Join** is a SQL operation used to query and merge rows from two or more tables based on a related column between them. This related column is almost always a **Primary Key (PK)** in one table that is referenced by a **Foreign Key (FK)** in another table.

```
       Primary Key                                 Foreign Key
    ┌──────────────┐                             ┌──────────────┐
    │  Customers   │                             │    Orders    │
    ├──────────────┤                             ├──────────────┤
    │ customer_id  │ <─────── Linked via ─────── │ customer_id  │
    │ name         │        Join Condition       │ order_date   │
    │ city         │                             │ amount       │
    └──────────────┘                             └──────────────┘
```

---

## 2. Why Joins are Necessary: An Analogy

Imagine a company directory. Instead of writing the department name, location, and manager in every employee's row, we store that information once in a `Departments` table. The `Employees` table simply contains a `dept_id`.

*   **Without Joins:** You would have to query the department ID for an employee first, and then write a separate query to search for that department's location.
*   **With Joins:** You can do both steps in a single SQL statement, letting the database engine handle the matching efficiently.

---

## 3. Classification of Joins

SQL Joins are categorized based on their logic, operators, and syntax:

### A. Logical Joins (Standard Set-Based Joins)
These define *which* rows from the participating tables are retained or discarded:
1.  **`INNER JOIN`**: Returns only rows that have matching values in both tables.
2.  **`LEFT JOIN` (Outer)**: Returns all rows from the left table, plus matching rows from the right table.
3.  **`RIGHT JOIN` (Outer)**: Returns all rows from the right table, plus matching rows from the left table.
4.  **`FULL JOIN` (Outer)**: Returns all rows when there is a match in either the left or right table.
5.  **`CROSS JOIN`**: Returns the Cartesian product (every row in A paired with every row in B).
6.  **`SELF JOIN`**: A table joined with itself to query hierarchical data.

### B. Operator-Based Joins (How rows match)
These define *how* the columns are compared:
1.  **`EQUI JOIN`**: Uses the equality operator (`=`) to join tables.
2.  **`NON-EQUI JOIN`**: Uses operators other than equality (`<`, `>`, `!=`, `BETWEEN`, etc.) to join tables.

### C. Syntactic / Implicit Joins
1.  **`NATURAL JOIN`**: Implicitly joins tables on **all** columns that share the same name and data type, without needing an explicit `ON` clause.
