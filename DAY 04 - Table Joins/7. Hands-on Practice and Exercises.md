## 📊 Database Schema Setup

Run the following script to create and populate the practice database:

```sql

USE day4_practice;

-- Drop dependent tables first
DROP TABLE IF EXISTS OrderDetails;
DROP TABLE IF EXISTS Orders;
DROP TABLE IF EXISTS Products;
DROP TABLE IF EXISTS Customers;
DROP TABLE IF EXISTS DiscountRules;

-- 1. Customers Table
CREATE TABLE Customers (
    customer_id INT PRIMARY KEY,
    name VARCHAR(50),
    email VARCHAR(50),
    city VARCHAR(50)
);

-- 2. Products Table
CREATE TABLE Products (
    product_id INT PRIMARY KEY,
    product_name VARCHAR(50),
    price DECIMAL(10,2)
);

-- 3. Orders Table (Allows NULL customer_id for full outer join testing)
CREATE TABLE Orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    order_date DATE,
    total_amount DECIMAL(10,2),
    FOREIGN KEY (customer_id) REFERENCES Customers(customer_id)
);

-- 4. OrderDetails Table
CREATE TABLE OrderDetails (
    order_id INT,
    product_id INT,
    quantity INT,
    PRIMARY KEY (order_id, product_id),
    FOREIGN KEY (order_id) REFERENCES Orders(order_id),
    FOREIGN KEY (product_id) REFERENCES Products(product_id)
);

-- 5. DiscountRules Table (for Non-Equi Join practice)
CREATE TABLE DiscountRules (
    discount_level VARCHAR(20),
    min_spend DECIMAL(10,2),
    max_spend DECIMAL(10,2),
    discount_percent INT
```

## 🟢 Practice Exercises & Solutions

### Q1. Retrieve Customer Names and Their Order Dates (Equi Join)
Write a query to list all customer names alongside their order IDs and order dates. Only return orders placed by registered customers.

*   **Query**:
    ```sql
    SELECT c.name AS customer_name, o.order_id, o.order_date
    FROM Customers c
    INNER JOIN Orders o ON c.customer_id = o.customer_id;
    ```
*   **Expected Output**:
    | customer_name | order_id | order_date |
    | :--- | :--- | :--- |
    | Alice | 1001 | 2026-07-20 |
    | Alice | 1003 | 2026-07-22 |
    | Bob | 1002 | 2026-07-21 |
    | David | 1004 | 2026-07-23 |

---

### Q2. List Customer Names and Order Totals Including Those with No Orders (Left Join)
Write a query to display all customer names and the total amount of their orders. If a customer has not placed an order, show `NULL` or `0` for the order amount.

*   **Query**:
    ```sql
    SELECT c.name AS customer_name, COALESCE(o.total_amount, 0) AS total_spent
    FROM Customers c
    LEFT JOIN Orders o ON c.customer_id = o.customer_id;
    ```
*   **Expected Output**:
    | customer_name | total_spent |
    | :--- | :--- |
    | Alice | 52000.00 |
    | Alice | 12000.00 |
    | Bob | 15000.00 |
    | Charlie | 0.00 |
    | David | 2000.00 |
    | Eve | 0.00 |

### Q3. Find Customer Names and Product Names Ordered (Multi-Table Join)
Write a query to display customer names, product names ordered, and quantity. (Requires joining `Customers`, `Orders`, `OrderDetails`, and `Products`).

*   **Query**:
    ```sql
    SELECT c.name AS customer_name, p.product_name, od.quantity
    FROM Customers c
    INNER JOIN Orders o ON c.customer_id = o.customer_id
    INNER JOIN OrderDetails od ON o.order_id = od.order_id
    INNER JOIN Products p ON od.product_id = p.product_id;
    ```
*   **Expected Output**:
    | customer_name | product_name | quantity |
    | :--- | :--- | :--- |
    | Alice | Laptop | 1 |
    | Alice | Earbuds | 1 |
    | Bob | Mobile | 1 |
    | Alice | Tablet | 1 |
    | David | Earbuds | 1 |

### Q4. Match Orders to Their Discount Brackets (Non-Equi Join)
Display all order IDs, order total amounts, and their applicable discount percentage based on their spending level. (Hint: Join `Orders` and `DiscountRules` using a range comparison).

*   **Query**:
    ```sql
    SELECT o.order_id, o.total_amount, dr.discount_level, dr.discount_percent
    FROM Orders o
    INNER JOIN DiscountRules dr ON o.total_amount BETWEEN dr.min_spend AND dr.max_spend;
    ```
*   **Expected Output**:
    | order_id | total_amount | discount_level | discount_percent |
    | :--- | :--- | :--- | :--- |
    | 1001 | 52000.00 | Gold | 10 |
    | 1002 | 15000.00 | Silver | 5 |
    | 1003 | 12000.00 | Silver | 5 |
    | 1004 | 2000.00 | Bronze | 0 |
    | 1005 | 7000.00 | Silver | 5 |

### Q5. Emulate FULL OUTER JOIN (Include all customers and guest orders)
Write a query to list all customer names and all order IDs in the database, including customers who haven't ordered, and guest orders that have no matching customer record.

*   **Query**:
    ```sql
    SELECT c.name AS customer_name, o.order_id
    FROM Customers c
    LEFT JOIN Orders o ON c.customer_id = o.customer_id
    
    UNION
    
    SELECT c.name AS customer_name, o.order_id
    FROM Customers c
    RIGHT JOIN Orders o ON c.customer_id = o.customer_id;
    ```
*   **Expected Output**:
    | customer_name | order_id |
    | :--- | :--- |
    | Alice | 1001 |
    | Alice | 1003 |
    | Bob | 1002 |
    | Charlie | NULL |
    | David | 1004 |
    | Eve | NULL |
    | NULL | 1005 |

### Q6. Pair Customers in the Same City (Self Join)
List unique pairs of customers who live in the same city, ensuring a customer is not paired with themselves and duplicate pairs are eliminated.

*   **Query**:
    ```sql
    SELECT c1.name AS customer_1, c2.name AS customer_2, c1.city
    FROM Customers c1
    INNER JOIN Customers c2 ON c1.city = c2.city AND c1.customer_id < c2.customer_id;
    ```
*   **Expected Output**:
    | customer_1 | customer_2 | city |
    | :--- | :--- | :--- |
    | Alice | Charlie | Delhi |
