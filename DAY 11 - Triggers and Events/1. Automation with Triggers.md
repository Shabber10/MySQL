# Day 11: Chapter 1 — Automation with Triggers

A **Trigger** is a named database object that automatically executes (or "fires") a set of SQL statements in response to a specific data event (`INSERT`, `UPDATE`, or `DELETE`) on a specified table.

Triggers are ideal for enforcing complex business rules, maintaining audit logs, and keeping derived data in sync automatically.

---

## ⚡ 1. Trigger Mechanics: Timing & Events

A trigger is defined by two key parameters:
1. **Trigger Event:** The DML operation that causes the trigger to execute (`INSERT`, `UPDATE`, or `DELETE`).
2. **Trigger Timing:** Determines whether the trigger code executes **before** or **after** the table modification is processed.
   * **`BEFORE`:** Fires before the change is written to the table. Used for validating or modifying data before insertion/update.
   * **`AFTER`:** Fires after the change is written. Used for logging, audit trails, or updating related tables.

### Combination Matrix
| Timing | Event | Typical Use Case |
| :--- | :--- | :--- |
| **`BEFORE`** | `INSERT` | Validate input values, set default timestamps, encrypt sensitive data. |
| **`AFTER`** | `INSERT` | Insert a record into an audit log table, increment counter caches. |
| **`BEFORE`** | `UPDATE` | Prevent unauthorized changes, validate salary caps. |
| **`AFTER`** | `UPDATE` | Log price change history (`old_price` -> `new_price`). |
| **`BEFORE`** | `DELETE` | Prevent deletion of protected accounts or soft-delete instead. |
| **`AFTER`** | `DELETE` | Log deleted records to an archival table for compliance. |

---

## 🔍 2. Accessing Modifying Data: `NEW` and `OLD`

Inside a trigger body, MySQL provides access to the rows being affected using two pseudo-row keywords:

* **`NEW`:** Refers to the new row data being inserted or updated.
* **`OLD`:** Refers to the existing row data before an update or deletion.

| Event | `OLD` Availability | `NEW` Availability |
| :--- | :--- | :--- |
| **`INSERT`** | ❌ Unavailable | ✅ Available (`NEW.column_name`) |
| **`UPDATE`** | ✅ Available (`OLD.column_name`) | ✅ Available (`NEW.column_name`) |
| **`DELETE`** | ✅ Available (`OLD.column_name`) | ❌ Unavailable |

## 🛠️ 3. Creating a Trigger

### Syntax:
```sql
DELIMITER //

CREATE TRIGGER trigger_name
BEFORE | AFTER    INSERT | UPDATE | DELETE
ON table_name
FOR EACH ROW
BEGIN
    -- Trigger SQL logic
END //

DELIMITER ;
```

> **Note:** `FOR EACH ROW` specifies that the trigger executes once for every single row affected by the DML statement.

## 💻 4. Practical Examples

### Example 1: Audit Log Trigger (`AFTER UPDATE`)
Log salary changes into an audit table whenever an employee's salary is modified.

```sql
-- 1. Create Audit Table
CREATE TABLE SalaryAudit (
    audit_id INT PRIMARY KEY AUTO_INCREMENT,
    emp_id INT,
    old_salary DECIMAL(10,2),
    new_salary DECIMAL(10,2),
    changed_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    changed_by VARCHAR(50)
);

-- 2. Create AFTER UPDATE Trigger
DELIMITER //

CREATE TRIGGER log_salary_change
AFTER UPDATE ON Employees
FOR EACH ROW
BEGIN
    IF OLD.salary <> NEW.salary THEN
        INSERT INTO SalaryAudit (emp_id, old_salary, new_salary, changed_by)
        VALUES (OLD.emp_id, OLD.salary, NEW.salary, CURRENT_USER());
    END IF;
END //

DELIMITER ;

-- Test Trigger:
UPDATE Employees SET salary = 70000.00 WHERE emp_id = 1;

-- Inspect Audit Log:
SELECT * FROM SalaryAudit;
```

### Example 2: Input Validation Trigger (`BEFORE INSERT`)
Enforce a business rule: salary cannot be negative. If negative, reset it to 0.00.

```sql
DELIMITER //

CREATE TRIGGER validate_salary_before_insert
BEFORE INSERT ON Employees
FOR EACH ROW
BEGIN
    IF NEW.salary < 0 THEN
        SET NEW.salary = 0.00;
    END IF;
END //

DELIMITER ;

-- Test Trigger:
INSERT INTO Employees (name, department, salary, city) 
VALUES ('Error Test', 'IT', -5000.00, 'Delhi');

-- Check result (salary was adjusted to 0.00 automatically)
SELECT * FROM Employees WHERE name = 'Error Test';
```

## 🗑️ 5. Managing Triggers

### View All Triggers:
```sql
SHOW TRIGGERS;
-- Or query information_schema:
SELECT trigger_name, event_manipulation, event_object_table, action_timing 
FROM information_schema.triggers 
WHERE trigger_schema = 'day11_practice';
```

### Drop a Trigger:
```sql
DROP TRIGGER IF EXISTS log_salary_change;
```
